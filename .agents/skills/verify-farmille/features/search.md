# 資材を探す

作物、悩み、資材名を入力し、検索結果から資材を選ぶ。

## Sub-features

- search-home：ホームの検索欄から結果へ移動する。
- search-nav：メインナビから検索画面へ移動する。
- search-query：検索画面で入力を変え、候補と結果を更新する。
- search-sort：口コミ数、評価、新着の順序を切り替える。
- search-empty-clear：一致しない入力で空状態を確認し、入力を消して一覧を戻す。
- search-filter：分類候補を選び、同分類のORと異分類のANDを確認する。

## How to get to it (user POV)

- `/`の「作物・悩み・資材名から探す」に入力して検索する。
- 下部の「メインナビ」から「探す」を選ぶ。
- `/search`を直接開く。共有された検索URLを開いた場合も条件が復元される。

## Driving it with Codex Browser

前提条件：公開資材が1件以上ある。ホームと検索画面の現在のスナップショットで以下のラベルを確認する。

- ホーム検索：`tab.playwright.getByRole("search", {name:"資材検索"}).getByRole("searchbox").fill("トマト")`を実行し、同じsearch内の`getByRole("button", {name:"検索", exact:true}).click()`で送信する。URLの`q=トマト`と結果欄の「該当 N 件」を確認する。
- 並び替え：`tab.playwright.getByLabel("並び替え").selectOption("rating")`を実行する。URLの`sort=rating`と選択表示を確認し、表示カードの評価が降順か確認する。比較できる複数件がなければ順序の確認だけskipとする。
- 空結果：`tab.playwright.getByLabel("資材の検索条件").fill("検証用該当なし987654321")`を実行する。「条件に合う資材が見つかりませんでした」と0件を確認する。検索は入力後にURLが更新されるため、結果が更新された状態を読む。
- 解除：同じ入力を`fill("")`で消す。`q`がURLから消え、資材カードが再表示されることを確認する。選択済みの分類がある場合は「すべて解除」を使う。
- ナビ：ホームへ戻り、`getByRole("navigation", {name:"メインナビ"}).getByRole("link", {name:"探す", exact:true}).click()`を実行する。`/search`への遷移を確認する。
- 分類：入力欄で「トマト」を検索し、表示された分類候補のボタンをラベルで選ぶ。選択済みチップとURLの`filters`を確認する。複数分類の組合せと期待結果は`e2e/04-search.spec.ts`の検証条件に対応させる。
- URL復元：条件付きの結果画面で`tab.reload()`を実行し、検索値、選択チップ、並び順が残ることを確認する。

## Gotchas

- ホームには検索欄以外のリンクもある。検索ボタンは`role=search`内に限定する。
- 件数と資材名はDBに依存する。固定値を期待せず、実行時の値を証跡へ記録する。
- 375pxではページ見出しが視覚的に隠れる場合がある。可視の検索欄と結果欄で到達を確認する。
- `e2e/04-search.spec.ts`はDBに資材とユーザーを作る。閲覧専用の検証として実行しない。
- 開発モードのNext.jsボタンが左下の「ホーム」に重なる場合がある。ホームを検証開始点に戻す用途なら`tab.goto("http://127.0.0.1:3107/")`を使い、そこから「探す」をクリックする。「ホーム」のクリック成功には数えない。
