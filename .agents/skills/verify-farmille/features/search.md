# 資材を探す

作物、悩み、資材名を入力し、検索結果から資材を選ぶ。

## Sub-features

- search-home：ホームの検索欄から結果へ移動する。
- search-nav：メインナビから検索画面へ移動する。
- search-query：検索画面で入力を変え、候補と結果を更新する。
- search-sort：口コミ数、評価、新着の順序を切り替える。
- search-empty-clear：一致しない入力で空状態を確認し、入力を消して一覧を戻す。
- search-filter：分類候補を選び、同分類のORと異分類のANDを確認する。

## How to get to it (user POV)

- `/`の「作物・悩み・資材名から探す」に入力して検索する。
- 下部の「メインナビ」から「探す」を選ぶ。
- `/search`を直接開く。共有された検索URLを開いた場合も条件が復元される。
- 375pxの検索画面では、結果の上の「絞り込み」や区分のチップ（効果分類・資材ジャンル・作物・メーカー・施用方法）から絞り込みのシートを開く。

## Driving it with Playwright

前提条件：公開資材が1件以上ある。ホームと検索画面の現在のariaスナップショットで以下のラベルを確認する。

- ホーム検索：`page.getByRole("search", {name:"資材検索"}).getByRole("searchbox").fill("トマト")`を実行し、同じsearch内の`getByRole("button", {name:"検索", exact:true}).click()`で送信する。URLの`q=トマト`と結果欄の「該当 N 件」を確認する。
- 並び替え：Base UIのSelectなので`selectOption`は使えない。`page.getByLabel("並び替え").click()`で開き、`page.getByRole("option", {name:"評価が高い順", exact:true}).click()`で選ぶ（`e2e/support/ui.ts`の`chooseOption`と同じ操作）。URLの`sort=rating`と選択表示を確認する。作物の条件（作物の分類を選んだときや、「トマト」のように入力が作物名に一致したとき）があると、結果は見出し「「<作物名>」の記載がある資材 N件」と「作物分類として記載のある資材 N件」の2群に分かれ、並び順は群ごとに適用される。この場合は全カードを通した順序を期待せず、見出しごとの`section`（`page.locator("section").filter({has: page.getByRole("heading", {level:2, name:/記載(が|の)ある資材/})})`）内でカードの評価が降順か確認する。全体の順序は、`e2e/04-search.spec.ts`と同じく作物を含まない条件（資材名・メーカー・資材ジャンルなど）で確かめる。評価の表示がないカード（感想口コミ0件）は各群の末尾に来る。比較できる複数件がなければ順序の確認だけskipとする。
- 空結果：`page.getByRole("combobox", {name:"資材の検索条件"}).fill("検証用該当なし987654321")`を実行する。「条件に合う資材が見つかりませんでした」と0件を確認する。検索は入力の300ms後にURLが更新されるため、結果が更新された状態を読む。入力欄の下に出る「…に一致する候補がありません」は候補の案内で、検索結果ではない。
- 解除：同じ入力を`fill("")`で消す。`q`がURLから消え、資材カードが再表示されることを確認する。選んだ分類は、チップの「<名前>を外す」で1件ずつ外すか、375pxでは結果の上の「すべての条件をクリア」で全部外す。
- ナビ：ホームへ戻り、`page.getByRole("navigation", {name:"メインナビ"}).getByRole("link", {name:"探す", exact:true}).click()`を実行する。`/search`への遷移を確認する。
- 分類：`page.getByRole("combobox", {name:"資材の検索条件"}).fill("トマト")`で候補を開き、`page.getByRole("option", {name:"トマト 作物", exact:true}).click()`で選ぶ。候補の名前は「<名前> <区分>」で、区分は作物・悩み・効果・栽培条件・資材ジャンル・メーカー・製品名。選ぶと入力欄が空になり、チップ（「トマトを外す」）、URLの`filters`、「絞り込み条件：トマト」が出る。同じ区分を足すと「A または B」、別の区分を足すと「A かつ B」になる。期待する結果は`e2e/04-search.spec.ts`の検証条件に対応させる。
- 絞り込みシート：375pxで`page.getByRole("button", {name:/^絞り込み/}).click()`を実行し、dialog「絞り込み」内の条件のリンクを選ぶ。下部の「N件を表示する」で閉じ、選んだ条件と件数が結果に反映されることを確認する。
- URL復元：条件付きの結果画面で`page.reload()`を実行し、検索値、選択チップ、並び順が残ることを確認する。

## Gotchas

- ホームには検索欄以外のリンクもある。検索ボタンは`role=search`内に限定する。
- 件数と資材名はDBに依存する。固定値を期待せず、実行時の値を証跡へ記録する。
- 375pxではページ見出しが視覚的に隠れる。可視の検索欄と結果欄で到達を確認する。
- 絞り込みシートの中にも同じ検索欄がある。シートを開いている間は、locatorをdialog「絞り込み」の内外どちらかに限定する。
- `e2e/04-search.spec.ts`はDBに資材とユーザーを作る。閲覧専用の検証として実行しない。
- 開発モードのNext.jsボタンが左下の「ホーム」に重なる場合がある。ホームを検証開始点に戻す用途なら`page.goto("http://127.0.0.1:3107/")`を使い、そこから「探す」をクリックする。「ホーム」のクリック成功には数えない。
