Farmille 現行アカウント登録フロー

source audit / 2026-09-05 / current implementation

公開の登録入口は2系統です。個人用の「一般ユーザー」と、審査制・法人共有の「メーカー」に分かれます。メーカーアカウントを利用できるのは農業資材メーカーだけです。運営は公開登録できる利用者種別ではなく、内部で発行する管理アカウントです。

  • メーカーは法人情報を申請し、運営承認後に初めて共有ログインが発行される
  • 運営はメールとパスワードに加えてTOTPによる2要素認証が必須
  • 一般ユーザーの立場は4択の内部属性とし、公開画面には表示しない

アカウント種別

一般ユーザー 個人用

匿名・ハンドルネームで参加する個人アカウント。レビュー、使用レポート、参考になった、検討リストを利用します。

認証
メールアドレス＋パスワード
account_type = general
DB
auth.users と profiles が1対1
メーカー 法人用

農業資材メーカーが使う法人アカウント。自社資材の変更申請、記事、エビデンスを管理します。

認証
承認後のログインID＋パスワード
account_type = seller
DB
承認後に auth.users と seller_accounts を紐付け
運営 内部管理

メーカー審査、資材正本、変更申請、通報、タグ、使用レポート編集局を扱う運営専用アカウントです。

認証
メール＋パスワード＋TOTP
account_type = admin かつ aal = aal2
発行
公開フォームなし。運用担当者がSupabase上で手動作成

    seller

    admin

登録・申請フロー

一般ユーザー

自己登録です。メール確認が必要かどうかはSupabase Authの設定によって分岐しますが、運営による審査はありません。

メーカー

申請とアカウント発行が分かれています。申請時点ではAuthユーザーもパスワードも作られず、審査中はログインできません。 

seller_accounts.status
  applied
    承認
      approved
        共有ログイン発行
        /sellers/login から /dashboard へ
    却下
      rejected
  approved
    凍結
      suspended
        メーカーログインを拒否
        凍結解除で approved に戻す

運営

公開登録フローはありません。本番ではSupabase Studioでメール＋パスワードのユーザーを作り、app_metadata.account_type = admin を付与します。

属性と権限の境界

一般ユーザーの表示情報

一般ユーザーが持つ表示情報は、ハンドルネームとアバターだけです。登録時に選ぶ立場は内部属性としてDBに保持し、公開ビューや投稿には出しません。地域、主な作目、栽培形態、所属、一言、外部リンクは登録フォームでもDBでも保持しません。

画面上の名称 内部の権限値 責務
一般ユーザー account_type = general レビュー、使用レポート、保存
メーカー account_type = seller 自社資材とメーカー記事の管理
運営 account_type = admin 審査、資材正本、通報、編集局
同じログインでの兼用

現状の account_type は1つの値です。一般ユーザー権限とメーカー権限を同じログインへ重ねる仕組みはありません。メーカーの担当者が個人としてレビューも投稿する場合は、法人共有のメーカーアカウントとは別に一般ユーザーアカウントを使う構造です。メーカーメンバーの個別ログインはPhase 2です。

登録後の利用範囲

状態 主な入口 できること
非ログイン /、/search、各詳細 公開コンテンツの閲覧。投稿、参考になった、保存は不可
一般ユーザー /login、/me、/post レビュー・使用レポート、参考になった、検討リスト、プロフィール
メーカー /sellers/login、/dashboard 自社資材の確認・変更申請・追加申請・掲載終了申請、記事管理
運営 /login、/admin/mfa、/admin メーカー審査、資材正本・変更申請、通報、タグ、編集局

現行実装の注意点

メール連絡は一部が運用対応

メーカーの受付完了画面は「審査結果を連絡先メールへ送る」と案内しています。一方、現行コードの承認処理はログインIDと初期パスワードを運営画面へ一度だけ表示するところまでで、審査結果メールの自動送信処理はありません。運営が安全な手段で申請者へ伝える運用です。

  • 一般ユーザーの確認メールとパスワード再設定メールはSupabase Authを使う
  • 運用記録では本番Supabaseの独自SMTPが未設定で、メール到達性にリスクがある
  • メーカーの連絡先メールは内部情報であり、ログインIDや公開プロフィールには使わない
  • メーカーが凍結中、却下、審査中の場合は同じ認証エラーとして扱い、状態を外部へ推測させない

用語

一般ユーザー 個人として投稿・保存するアカウント
メーカー 農業資材メーカー専用の法人アカウント。コードでは seller
共有ログイン 組織内で共用する1つのログインID。個別メンバー管理は未実装
AAL2 パスワードにTOTPを加えた2要素認証済み状態
TOTP 認証アプリが生成する6桁コードを使う方式
合成メール メーカーのログインIDをAuth内部のメール形式へ変換した値。画面には出さない
