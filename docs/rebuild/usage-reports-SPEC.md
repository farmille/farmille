# 実証詳細レポートと感想口コミ

原稿は[入力・記事仕様](https://docs.google.com/document/d/1Z2bXQUD9D-N0XAfSdvZaSPB_O9uuXtfG7SSj9gAVwus/edit?tab=t.6oybnignmzui)を参照する。

## 実証詳細レポート

入力は1ページ。上に属性（資材・使用対象作目・品種・使用目的・地域・施用時期・投稿者名）、その下に文書（結果・感想、栽培環境、処理日と生育状況、比較・使用結果、確認）を並べる。タイトルは「資材名 実証詳細レポート｜作物名」を自動で表示し、投稿者は編集しない。未入力でも下書き保存とプレビューを使える。

属性の資材・使用対象作目・使用目的・施用時期は、押すと画面中央のポップアップで選ぶ。資材は資材名・メーカー名で検索する。使用対象作目は作物マスタから1件を選び、検索前から「この資材の登録作物」「あなたの栽培作目」「すべての作物」を並べる。品種はその場で書くか「不明・なし」を選ぶ。使用目的は効果タグを複数選び、補足を任意で書く。使用目的と施用時期のポップアップは右下に常に「完了」を置き、背景を押して閉じても選んだ内容を残す。地域は登録住所の都道府県を初期値とし、「市区町村も表示」を選んだ場合だけ市区町村を書く。施用時期は栽培の段階を複数選び、スマホでは縦一列、PCでは横一列に並べる。投稿者名はアカウントのニックネームを表示し、レポートごとには変えない。

文章の欄は記入例を常に表示し、書き始めると記入例は欄の下へずれて残る。「処理日と生育状況」の直下に「資材を使った日（処理日）を記入した」のチェックを置く。

比較・使用結果は、比べた区、調査項目ごとの結果の順とする。比べた区は2つ以上で、各区は名前と説明の2欄を持つ。説明には調査した範囲と資材の使い方を書き、差し込む資料を見ればわかる場合は「資料を参照」と書いてよいことを目立つ形で案内する。調査した範囲の欄は持たない。

調査項目ごとの結果は、調査項目名を先に書き、項目ごとに「資料のグラフ・表を差し込む」か「文章で書く」を選ぶ。調査項目は1つ以上とし、すべての項目を完成させる。文章はページ上で区ごとの結果を書く。資料はポップアップで写真（JPEG・PNG・WebP）とPDFを選び、PDFは使うページを選んで画像にする。画像は回転・切り取り・塗りつぶしで編集し、画像のタイトルを任意で付ける。保存するのは編集後の画像だけで、元の写真とPDFは保存しない。資料の項目は画像1枚以上で完成とし、ページに戻って補足説明を任意で書ける。入力用のポップアップを途中で閉じるときは確認し、新しい項目は書いた分をページに残し、変更中の項目は変更前に戻す。グラフを作る入れ方は持たない。5段階版で保存した数値グラフは、ページ版で開いたときに読み込まない。

記事は結果・感想、期待した効果、栽培条件・施用時期、比較・使用結果の順に表示する。比較・使用結果は比べた区の名前と説明、調査項目ごとの項目名・画像・文章を並べる。入力の区の色と記事の区の色を揃え、区1は灰色、区2は緑、区3は青緑とする。見出しの編集、節ごとの写真添付、関連資料の欄は持たない。既存のレポートに保存済みの見出しと関連資料は保持する。市区町村は公開を選んだ場合だけ記事に出し、非公開の値は専用テーブルに保存する。登録時の住所からは市区町村を写さない。記事に出す市区町村は著者が入力する。

上の帯に下書き保存とプレビューを置く。プレビューは公開後の記事の見え方を全画面で出し、未記入の項目があれば件数と名前を示す。

写真と差し込んだ画像は既存のreport-mediaに保存する。表示する写真のURLは投稿者の保存パスを確認し、設定済みのStorageに解決する。既存の関連資料のPDFは非公開のreport-documentsに残し、閲覧には有効期限付きURLを使う。

確認は、資材を使った区の説明に施用方法・希釈倍率・使用量・回数などを記入したこと（または「資料を参照」と書いたこと）、投稿ガイドラインへの同意とする。資料を差し込んだ場合は、氏名や連絡先が写っていないことと、秘密保持契約に反しないことの確認を加える。処理日と写り込みの確認は画面でだけ確かめ、保存しない。

提出時には必要項目と確認を検証し、未記入があれば項目名を並べて最初の未記入の項目へ移れるようにする。提出後は運営の確認中となり、運営の公開操作で記事になる。匿名閲覧の会員ゲートと既存記事の表示は維持する。下書き保存は更新日時を照合し、別画面で更新済みの場合は上書きせず入力を残して案内する。

親レコードはform_versionで入力形式を区別し、新形式を2とする。区、施用手順、対象、調査項目、グラフ、値、見出し、施用時期、資料は子テーブルに保存する。JSONは検証済みの入力をRPCへ渡す用途に限る。型と検証はsrc/lib/usage-report.ts、DB操作はsrc/server/usage-reports/structured.tsに置く。

## 感想口コミ

比較区の有無と購入場所の入力は廃止する。既存の保存値は保持し、新規入力や集計表示には利用しない。使用対象作目、感想、評価、写真、投稿前の同意は投稿・編集の両方で扱う。

## 検証

375pxの実画面で下書き保存、再読込、写真・PDFの差し込みと画像の編集、提出、記事の市区町村の非表示を確認する。E2Eは下書きから提出までと未公開記事の404を検証する。DBの権限、入力制約、同時更新はsupabase/tests/structured_usage_reports.test.sqlで検証する。
