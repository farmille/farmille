# 実証詳細レポートと感想口コミ

2026年9月29日の[入力・記事仕様](https://docs.google.com/document/d/1Z2bXQUD9D-N0XAfSdvZaSPB_O9uuXtfG7SSj9gAVwus/edit?tab=t.6oybnignmzui)を反映する。

## 実証詳細レポート

入力は「資材・作物」「結果」「栽培条件」「比較・使用結果」「写真・記事の確認」の5段階。作物は1件を選び、品種は任意とする。未入力でも下書き保存とプレビューを使える。

比較する区を2つ以上作り、各区の名前、調査範囲、説明を保存する。区は全グラフで共有する。ステップ4は結果のグラフ、区の説明、施用条件の明記確認、任意の「グラフにしにくい調査結果」の順とする。数値を含むグラフを1つ以上必須とし、任意文章が空の場合は保存しない。

空の縦棒グラフから調査項目、単位、区名、数値を入力する。調査項目の候補から単位を補完するが、手入力した単位は上書きしない。同じ調査項目の時期別グラフは直後へ、別の調査項目は末尾へ追加する。削除直後は取り消せる。数値の誤差や有意差記号は原文を残し、先頭数値と±の誤差を棒へ反映する。%の目盛りは100以上とし、多数の区はグラフ内で横スクロールする。

記事では同じ調査項目・単位のグラフを1節にまとめる。入力の縦棒、記事の横棒、区カードの色を揃え、区1は灰色、区2は緑、区3は青緑とする。比較した区はプレビューでも静的なカードで表示し、修正はステップ4で行う。施用方法タグは入力・記事とも表示しない。

記事は結果・感想、期待した効果、栽培条件・施用時期、比較した区、使用結果の詳細、関連資料の順に表示する。見出しと本文をプレビューで編集でき、写真は節ごとに添付する。市区町村は公開を選んだ場合だけ記事に出し、非公開の値は専用テーブルに保存する。登録時の住所からは市区町村を写さない。記事に出す市区町村は著者が入力する。

写真は既存のreport-media、PDFは非公開のreport-documentsに保存する。表示する写真のURLは投稿者の保存パスを確認し、設定済みのStorageに解決する。PDFの閲覧には有効期限付きURLを使う。資料を添付した場合は秘密保持に反しないことの確認を必須とする。

提出時には必要項目、施用条件の記載確認、投稿ガイドラインへの同意を検証する。提出後は運営の確認中となり、運営の公開操作で記事になる。匿名閲覧の会員ゲートと既存記事の表示は維持する。下書き保存は更新日時を照合し、別画面で更新済みの場合は上書きせず入力を残して案内する。

親レコードはform_versionで入力形式を区別し、新形式を2とする。区、施用手順、対象、調査項目、グラフ、値、見出し、施用時期、資料は子テーブルに保存する。JSONは検証済みの入力をRPCへ渡す用途に限る。型と検証はsrc/lib/usage-report.ts、DB操作はsrc/server/usage-reports/structured.tsに置く。

## 感想口コミ

比較区の有無と購入場所の入力は廃止する。既存の保存値は保持し、新規入力や集計表示には利用しない。使用作物、使用方法、感想、評価、写真、投稿前の同意は投稿・編集の両方で扱う。

## 検証

375pxの実画面で下書き保存、再読込、写真・PDF添付、見出し編集、提出、記事のグラフと市区町村の非表示を確認する。E2Eは下書きから提出までと未公開記事の404を検証する。DBの権限、入力制約、同時更新はsupabase/tests/structured_usage_reports.test.sqlで検証する。
