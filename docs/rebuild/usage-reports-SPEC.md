# 実証詳細レポートと感想口コミ

原稿は[入力・記事仕様](https://docs.google.com/document/d/1Z2bXQUD9D-N0XAfSdvZaSPB_O9uuXtfG7SSj9gAVwus/edit?tab=t.6oybnignmzui)を参照する。

## 実証詳細レポート

入力は1ページ。上に属性（資材・作物・品種・使用目的・地域・施用時期・投稿者名）、その下に文書（結果・感想、栽培環境、処理日と生育状況、比較・使用結果、確認）を並べる。タイトルは「資材名 実証詳細レポート｜作物名」を自動で表示し、投稿者は編集しない。未入力でも下書き保存とプレビューを使える。

属性の資材・作物・使用目的・施用時期は、押すと画面中央のポップアップで選ぶ。資材は資材名・メーカー名で検索する。作物は作物マスタから1件を選び、検索前から「この資材の登録作物」「あなたの作物」「すべての作物」を並べる。品種はその場で書くか「不明・なし」を選ぶ。品種が2つ以上のときは、品種ごとの欄で名前を直す。使用目的は効果タグを複数選び、補足を任意で書く。使用目的と施用時期のポップアップは右下に常に「完了」を置き、背景を押して閉じても選んだ内容を残す。地域は登録住所の都道府県を初期値とし、「市区町村も表示」を選んだ場合だけ市区町村を書く。施用時期は栽培の段階を複数選び、スマホでは縦一列、PCでは横一列に並べる。投稿者名はアカウントのニックネームを表示し、レポートごとには変えない。

区は、試した品種と使った資材の組み合わせ1つにあたる。品種はレポートに一覧で持ち、「品種が不明、または品種がない」ときは空にする。区は一覧の品種を1つ指す。下書きから提出するときは、どの区からも指されていない品種を、品種名を示して断る（品種の行は自動では消さない）。使った資材は、投稿した資材・比較した資材・無処理のいずれかで、投稿した資材を使った区を1つ以上入れる。比較した資材は名前でレポートに足し、資材のカタログには紐づけない。量や回数の違いは、同じ資材の区を名前と説明で分ける。区・品種・比較した資材はそれぞれ40まで。新しく作るレポートは、品種1つと「無処理」「投稿した資材」の2区から始める。

全区に共通の説明を1つ書け、区ごとの説明には違いだけを書く。提出時は、区ごとの説明か共通の説明のどちらかがあればよい。品種と使った資材の必須は、下書きから提出するときだけ確かめる。品種と使った資材を持たない既存のレポートも、そのまま公開でき、記事では今の1列の見え方で出す。

調査項目は1つ以上を必須とし、結果は数値のグラフ、資料のグラフや表の画像、文章のいずれかで入れる。数値の調査項目はグラフが1つ以上要り、各グラフは全区の行を1行ずつ持ち、数値として読める値を1つ以上持つ。測っていない区の値は空欄でよく、空欄の区は公開のグラフに出さない。画像の調査項目は画像が1枚以上、文章の調査項目は本文が要る。区の調査範囲は保存するが、提出の必須にはしない。調査項目に差し込んだ画像は、一覧の表紙に使わない。

文章の欄は記入例を常に表示し、書き始めると記入例は欄の下へずれて残る。「処理日と生育状況」の直下に「資材を使った日（処理日）を記入した」のチェックを置く。

比較・使用結果は、比べた区、調査項目ごとの結果の順とする。比べた区では、試した品種と使った資材をチップで並べ、「品種を足す」「比較した資材を足す」で増やす。投稿した資材と無処理のチップは外せない。品種が2つ以上か比較した資材があるとき、または品種1つの無処理と投稿した資材の区が欠けたときだけ「試した組み合わせ」の表（品種×資材のチェック）を出し、チェックした組み合わせが区になる。品種や資材を足すと、その品種・資材の組み合わせをすべて区にする。表を出さないときは、今の区のまま名前と説明を書き、「区を追加」で投稿した資材の区を足す（量や回数の違いを分ける区）。区は2つ以上で、各区は名前と説明の2欄を持つ。区の名前は品種と資材から自動で付け（品種1つなら「資材名区」、2つ以上なら「品種・資材名」、同じ組み合わせの2つ目からは番号を付ける）、書き換えた名前は組み合わせや品種名を変えても上書きしない。全区に共通の説明は、表を出すときか記入済みのときに出す。区に使った資材の無い下書きは、区ごとに資材を選ぶ。説明には調査した範囲と資材の使い方を書き、差し込む資料を見ればわかる場合は「資料を参照」と書いてよいことを目立つ形で案内する。調査した範囲の欄は持たない。

調査項目ごとの結果は、調査項目名を先に書き、項目ごとに「資料のグラフ・表を差し込む」か「文章で書く」を選ぶ。調査項目は1つ以上30以下とし、すべての項目を完成させる。30に達したら追加の操作を出さず、上限を案内する。文章はページ上で区ごとの結果を書く。資料はポップアップで写真（JPEG・PNG・WebP）とPDFを選び、PDFは使うページを選んで画像にする。画像は回転・切り取り・塗りつぶしで編集し、画像のタイトルを任意で付ける。保存するのは編集後の画像だけで、元の写真とPDFは保存しない。資料の項目は画像1枚以上で完成とし、ページに戻って補足説明を任意で書ける。入力用のポップアップを途中で閉じるときは確認し、新しい項目は書いた分をページに残し、変更中の項目は変更前に戻す。数値のグラフを手で一から作る入れ方は持たない。PDF読み取りや5段階版で入った数値のグラフの調査項目は、読み取り専用のグラフで出し、「数値を直す」で調査項目名・単位・グラフの題・区ごとの値（「1126±139 B」のような原文の文字列）を直せる。数値のグラフの調査項目は削除できる。区を変えると、グラフの行を区ごとに1行へそろえる。

記事は結果・感想、期待した効果、栽培条件・施用時期、比較・使用結果の順に表示する。比較・使用結果は全区に共通の説明、比べた区の名前と説明、調査項目ごとの項目名・グラフ・画像・文章を並べる。入力の区の色と記事の区の色を揃える。全区が使った資材を持つときは資材で塗り（無処理は灰色、投稿した資材は緑、比較した資材は青緑・紫・橙の順）、品種が2つ以上なら区とグラフを品種ごとにまとめ、グラフに資材の色の凡例を付ける。使った資材の無い区がある既存のレポートは区の順に1列で並べ、区1は灰色、区2は緑、区3以降は青緑・紫・橙とする。見出しの編集、節ごとの写真添付、関連資料の欄は持たない。既存のレポートに保存済みの見出しと関連資料は保持する。調査項目に属さない既存の節ごとの写真・動画は、入力画面で「以前の形式の写真」として添えた欄と一緒に並べ、削除できる。プレビューでは記事と同じく添えた節の最後に出す。市区町村は公開を選んだ場合だけ記事に出し、非公開の値は専用テーブルに保存する。登録時の住所からは市区町村を写さない。記事に出す市区町村は著者が入力する。

上の帯に下書き保存とプレビューを置く。プレビューは公開後の記事の見え方を全画面で出し、未記入の項目があれば件数と名前を示す。

写真と差し込んだ画像は既存のreport-mediaに保存する。report-mediaは公開の置き場なので、保存で参照しなくなった画像（差し替え前の画像や削除した写真）は、下書きの保存がDBで済んだあとに投稿者のフォルダから消す。表示する写真のURLは投稿者の保存パスを確認し、設定済みのStorageに解決する。既存の関連資料のPDFは非公開のreport-documentsに残し、閲覧には有効期限付きURLを使う。

確認は、資材を使った区の説明に施用方法・希釈倍率・使用量・回数などを記入したこと（または「資料を参照」と書いたこと）、投稿ガイドラインへの同意とする。資料の画像を差し込んだ場合か既存の関連資料がある場合は、氏名や連絡先が写っていないことと、秘密保持契約に反しないことの確認を加える。差し込んだ画像についての秘密保持の確認は、下書きから提出するときに画面・サーバー・DBで確かめ、提出済みのレポートの公開では確かめない。処理日と写り込みの確認は画面でだけ確かめ、保存しない。

提出時には必要項目と確認を検証し、未記入があれば項目名を並べて最初の未記入の項目へ移れるようにする。提出後は運営の確認中となり、運営の公開操作で記事になる。匿名閲覧の会員ゲートと既存記事の表示は維持する。下書き保存は更新日時を照合し、別画面で更新済みの場合は上書きせず入力を残して案内する。

親レコードはform_versionで入力形式を区別し、新形式を2とする。品種、比較した資材、区、施用手順、対象、調査項目、グラフ、値、見出し、施用時期、資料は子テーブルに保存する。form_version=2の品種は親レコードのvariety列に書かない（判断の経緯は[ADR 0002](../adr/0002-plot-variety-and-material.md)）。JSONは検証済みの入力をRPCへ渡す用途に限る。型と検証はsrc/lib/usage-report.ts、DB操作はsrc/server/usage-reports/structured.tsに置く。

## 感想口コミ

比較区の有無と購入場所の入力は廃止する。既存の保存値は保持し、新規入力や集計表示には利用しない。使用対象作目、感想、評価、写真、投稿前の同意は投稿・編集の両方で扱う。

## 検証

375pxの実画面で下書き保存、再読込、写真・PDFの差し込みと画像の編集、提出、記事の市区町村の非表示を確認する。E2Eは下書きから提出までと未公開記事の404を検証する。DBの権限、入力制約、同時更新はsupabase/tests/structured_usage_reports.test.sqlで検証する。
