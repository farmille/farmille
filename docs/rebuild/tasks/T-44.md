# T-44 admin：出品者審査・資材登録／claim・検索補助タグ／作物管理

あなたは認可と Auth Admin API の扱いに厳密なエンジニアです。対象：`/admin`・`/admin/sellers`・`/admin/materials`・`/admin/tags`。仕様は `01-domain-model.md` §4（admin AAL2）・§6（状態遷移）・`02-screens.md` §2。admin UI はモック基準外（D4）＝キット部品の簡素なテーブル・フォームで機能優先。

## 制約

- 触ってよいのは `src/app/admin/`（reports・usage-reports 配下は T-45 の領域なので**作らない**）・`src/server/admin/`（新規）・components/ への追加（必要最小）
- 全ページ・全 Server Action で `requireAdmin()`（account_type='admin'＋**AAL2**）。書き込みは createAdminSupabase（service_role）でよいが、**必ず requireAdmin 通過後**
- admin アカウントの MFA enroll/challenge 画面もこのタスクで実装する（TOTP。supabase-js の mfa API。AAL1 admin は enroll へ誘導）

## 実装

1. **admin シード**：ローカル検証用に admin ユーザーを作る手順スクリプト（tools/dev/create-local-admin.ts 等。email+password で作成し app_metadata.account_type='admin' を Admin API で付与。**リモートでは実行しない旨を冒頭コメント**）
2. **`/admin`**：サマリー（申請中出品者数・open 通報数・pending 使用レポート数）＋各機能への導線
3. **`/admin/sellers`**：applied 一覧→詳細（内部項目含む）→**承認**（①合成メール `{login_id}@sellers.farmille.internal` で Auth ユーザー作成（初期パスワードは安全な乱数生成・画面に一度だけ表示）②app_metadata { account_type:'seller', seller_id } 付与 ③status='approved'・approved_at・auth_user_id 更新）／**却下**（status='rejected'・理由任意）／approved の**凍結**（suspended）。招待コード発行（invite_code 設定）
4. **`/admin/materials`**：資材一覧（全 status）・新規登録（種まき：分類・検索層＋一次情報の初期値）・編集（全カラム可）・**claim 紐づけ**（seller 選択→ materials.seller_id 設定・解除）・material_edit_requests の処理（open→done/declined）
5. **`/admin/tags`**：検索補助タグ・作物マスタの一覧・追加・改名・削除（使用中の行は削除不可＝参照カウント表示）。その他の分類マスタは初期値を使い、資材編集フォームから関連を選ぶ

## 検証（完了条件）

ゲート一式（pipefail）＋実フロー：admin 作成→MFA enroll→AAL2 で /admin 到達（AAL1 では aal2_required で enroll へ）。T-41 で作った applied 申請を承認→発行された ID/パスワードで /sellers/login からログインできる（**T-13 の出品者ログインと突合**）。資材の claim 紐づけ→公開側にメーカー確認済みバッジ。検索補助タグ追加→検索候補に出る。375px 必須ではない（admin は PC 想定可）が動作スクリーンショット添付。

## 質問すべき条件

- 承認フローで 01 §6 と実装が両立しない点が出たら停止して報告。初期パスワードの取り扱いで本指示より安全な代替（招待リンク等）を実装したい場合は、実装せず提案として報告

## 最終報告の形式

実装ファイル一覧／検証結果（承認→ログイン突合の証跡）／設計判断／未実装として残した点。
