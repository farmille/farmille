# T-11 v2 スキーマ migration 一式（テーブル・RLS・ビュー・集計・シード）

あなたは PostgreSQL と Supabase（RLS・Auth・Storage）に深く精通したデータベースエンジニアです。**このタスクの正は `docs/rebuild/01-domain-model.md`**。本指示書は手順と完了条件だけを定め、スキーマの内容は 01 に従うこと。

## 制約

- 触ってよいのは `supabase/` 配下と `frontend/src/types/database.types.ts` のみ
- リモート DB（--linked）には**絶対に接続しない**。検証はローカルスタック（Docker）のみ
- 適用済み migration の編集禁止の規約はこの v2 系にも適用：作業中でも修正は新規ファイルではなく、**未コミットのうちは同一ファイルを直してよい**が、コミット後の修正は新規ファイル
- 旧スキーマ（`tools/migration/legacy/migrations-v1/`）は読み取り参照のみ

## 手順

1. `npx supabase init`（`supabase/config.toml` を生成・コミット対象）→ `npx supabase start`（ローカルスタック起動。Docker 使用可）
2. v2 migration を作成（`npx supabase migration new <name>` で連番生成。分割方針：`init_accounts`／`init_materials_tags`／`init_posts`（reviews・usage_reports 系）／`init_collections_reports`（saved・helpful・view_events・content_reports・articles）／`init_phase2_qa`／`rls_policies`／`views_and_aggregates`／`seed_masters` の8本程度）
   - テーブル・カラム・CHECK・FK・UNIQUE は 01 §3 の定義どおり。全テーブルに updated_at 自動更新トリガー
   - RLS は 01 §5 の表どおり。**全テーブルで ENABLE ROW LEVEL SECURITY**。判定は `auth.jwt() -> 'app_metadata'` 直読み（テーブル JOIN しない）。admin は `account_type='admin'` かつ書き込み系は `aal = 'aal2'` も要求
   - 公開ビュー（01 §5）：`public_profiles`（standpoint・非公開 prefecture・内部項目を除外）・`public_sellers`（contact_* を除外・approved のみ）。security_invoker=true
   - materials の一次情報層のカラム単位権限：出品者の UPDATE は「一次情報層カラムのみ変更可」を**トリガーで強制**（旧値と新値を比較し、分類・検索層カラムの変更を検出したら例外）。admin は全カラム可
   - 集計（review_count・avg_rating・control_plot_ratio）：reviews の INSERT/UPDATE/DELETE トリガーで materials の非正規化カラムを更新する方式
   - Storage バケット5種（`avatars`・`material-images`・`review-photos`・`report-media`・`article-images`）の作成とパス強制 RLS（`{所有者id}/…` 先頭一致。avatars/review-photos=一般本人、material-images/article-images=出品者＋admin、report-media=一般本人）。公開読み取りは全バケット可
   - シード：tags（モックの語彙26件＋分類。抽出元は `docs/rebuild/reference/mockup-sp-19screens.html` 内の `TAGS`/`TAG_CATS` 定義を grep）・crop_groups／crops／aliases（同 `CROP_GROUPS`/`CROP_ALIASES`、12群・約45作物）
3. `npx supabase db reset`（ローカル）で全 migration がクリーンに通ることを確認
4. 検証 SQL を流して確認（少なくとも）：
   - 全テーブルの RLS 有効を pg_tables/pg_class で確認（0 件の漏れ）
   - anon ロールで published コンテンツが SELECT でき、INSERT が拒否されること（`set role anon` 相当のテスト。ローカル psql で `request.jwt.claims` を set してポリシー挙動を最低3ケース：匿名読める／一般ユーザーが自分のレビューを書ける／出品者はレビューを書けない）
   - reviews トリガーで materials.review_count・avg_rating が更新されること
5. `npx supabase gen types typescript --local > frontend/src/types/database.types.ts`
6. コミット（migration・config.toml・types。意味単位で分割可）

## 検証（完了条件）

- `npx supabase db reset` がエラーなしで完走するログ
- 手順4の検証 SQL の実行結果（貼付）
- `git status --short` クリーン

## 質問すべき条件

- 01-domain-model.md の定義に矛盾・実装不能な点を見つけた場合は、**勝手に設計変更せず**、その箇所と代替案を報告して停止する（カラム名の微修正・型の具体化など、意味を変えない具体化は裁量でよい。その場合は最終報告に列挙）

## 最終報告の形式

作成した migration ファイル一覧と各内容1行要約／検証結果（reset ログ末尾・検証 SQL の出力）／01 からの具体化・裁量判断の一覧。
