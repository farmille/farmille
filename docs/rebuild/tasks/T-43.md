# T-43 記事投稿・編集（出品者ダッシュボード）

あなたはエディタ UI の実装に丁寧なエンジニアです。対象：`/dashboard/articles`（一覧）・`/dashboard/articles/new`・`/dashboard/articles/[id]/edit`。仕様は `01-domain-model.md` §3 articles・`02-screens.md` §2。要件定義 2-3（記事投稿フォーム：タイトル必須・本文必須・画像挿入可・紐づけ資材は任意/複数/他社可）。

## 定型制約（04 §3・必須）

- 共通 UI キットで組む。不足部品はキット追加が先。ページ側 styled-system はレイアウト調整のみ
- モックに記事投稿画面は無い→ダッシュボード（T-42）と同じ視覚言語。完了報告は単独スクリーンショットで可

## その他の制約

- 触ってよいのは `src/app/dashboard/articles/`（新規）・`src/server/`（articles mutation 追加）・components/ への追加
- requireSeller()。自組織の記事のみ編集・削除可（RLS 保険）
- 本文は Markdown（プレーン textarea＋プレビュー切替で可。WYSIWYG は作らない）。画像は Storage `article-images`・パス `{seller の auth uid}/…` にアップロードして Markdown に URL 挿入。hero 画像は別枠

## 実装

1. **一覧**：自組織の記事（draft／published のバッジ・編集・削除・公開/非公開切替）
2. **新規/編集フォーム**：タイトル・hero 画像（任意）・本文（Markdown・画像挿入ボタン＝アップロード→URL 挿入・プレビュータブ）・紐づけ資材（検索して複数選択・他社資材も可＝materials 全体から）・下書き保存／公開
3. 公開後の確認導線（/articles/[id] へ）
4. 削除は確認ダイアログ。公開記事の削除は「非公開化を促す」文言つきで可

## 検証（完了条件）

ゲート一式（pipefail）＋実フロー：出品者で記事作成（画像1枚挿入・他社資材1件紐づけ）→公開→ /articles・/articles/[id]・紐づけ資材の詳細ページ「関連記事」に表示→編集→非公開化で公開側から消える。他組織の記事 URL 直叩きで notFound。スクリーンショット添付。

## 質問すべき条件

- Markdown レンダリング（lib/markdown/render.ts）で画像・見出しの sanitize 挙動に疑義が出たら停止して報告

## 最終報告の形式

実装ファイル一覧／検証結果／キット追加の有無／設計判断。
