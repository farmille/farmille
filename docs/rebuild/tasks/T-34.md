# T-34 参考になった・閲覧イベント整備・通報モーダル

あなたは丁寧な結線作業が得意なエンジニアです。仕様は `01-domain-model.md` §3（helpful_votes・view_events・content_reports）と `02-screens.md` §2。

## 制約

- 触ってよいのは `frontend/src/server/`（helpful/reports 系追加）・既存カード／詳細ページへの**結線のみ**（レイアウト変更禁止）・components/ への通報モーダル追加
- 要ログイン操作（helpful・通報）は未ログイン時ログイン誘導。server 層で検証・RLS は保険

## 実装

1. **参考になった**：レビューカード・使用レポート詳細・記事詳細の「参考になった」ボタンを実装（トグル・useOptimistic 可・個票 helpful_votes・UNIQUE 制約前提）。自分の投稿には押せない（server 検証）。押下数の表示は既存の集計値（helpful_counts）と整合
2. **閲覧イベントの整備**：T-24 実装分（reports/articles）を確認し、資材詳細にも view_events 記録を追加（target_type='material' が 01 の CHECK に無ければ**停止して報告**——確認の上で必要なら報告のみ。レビューへの記録は카ード表示単位では行わない）
3. **通報モーダル**：レビュー・使用レポート・記事・公開プロフィールの各所に「通報する」導線（控えめな配置。カードの … メニューか詳細フッター）→ モーダル（理由 select＋自由記述）→ content_reports へ INSERT。二重通報は UNIQUE でなくアプリ側で「対応中です」表示
4. 完了トースト・エラー文言はエラー辞書経由

## 検証（完了条件）

ゲート一式（pipefail）＋実フロー：一般ユーザー2人で相互に helpful（自分のには押せない）→ カウント反映→取り消し。通報1件→ content_reports に open で入る。375px スクリーンショット（helpful 押下状態・通報モーダル）。

## 質問すべき条件

- view_events の target_type CHECK に material が無い場合は migration を追加せず停止して報告

## 最終報告の形式

実装ファイル一覧／検証結果／結線した箇所の一覧／設計判断。
