# T-01 リポジトリ掃除（移設＋削除＋指示ファイル書換）

あなたは大規模リポジトリの整理を正確に行うエンジニアです。作業ディレクトリは `/Users/shun/Documents/farmille/farmille-T01`（git worktree・ブランチ `rebuild/t01`）。この worktree の外は一切触らないこと。

## 制約（先に読む）

- **`frontend/` 配下には一切触れない**（別タスクの領域）
- 削除は必ず `git rm`／`git rm -r`。ファイルシステム直接削除をしない
- `docs/rebuild/`・`docs/email-templates/`・`.github/`（存在しない）・`.gitignore` の既存内容は削除しない
- 適用済みの Supabase DB・リモートには一切触れない。これはファイル操作だけのタスク
- 新規作成してよいのは：`docs/ops/`・`tools/migration/legacy/`・`supabase/migrations/.gitkeep`・書き換え後の `AGENTS.md`/`CLAUDE.md` のみ

## 背景

アプリ全面刷新（設計の正＝`docs/rebuild/`、特に `05-cleanup.md`）。後方互換不要・旧仕様ドキュメントは削除方針。運用記録と移行材料だけ残す。

## 手順

1. **移設（削除より先）**
   - `mkdir docs/ops`
   - `docs/handoff/onboarding.md` の §9（既知の地雷）から、secret 事故（2026-07-04・Cloud Build への .env アップロード）・**service_role キーと JWT secret のローテーション未実施**・その他運用上有効な注意点を抽出し、`docs/ops/security-notes.md` を新規作成（1ページ・事実と日付を保持。鍵移行の手順概要は `docs/rebuild/03-architecture.md` §6 を参照させる）
   - `git mv docs/handoff/access-checklist.md docs/ops/access-checklist.md`
   - `mkdir -p tools/migration/legacy` して `backend/scripts/` の Python 9本を `git mv` で `tools/migration/legacy/` へ
   - 旧 migration 28本を退避：`git mv supabase/migrations tools/migration/legacy/migrations-v1` → `mkdir supabase/migrations && touch supabase/migrations/.gitkeep`（新スキーマ用に空ける。※05-cleanup では第2弾扱いだが、v2 migration との同居を避けるためここで退避する）
2. **削除（`docs/rebuild/05-cleanup.md` §2 のリストどおり）**
   - docs/：specs/・requirements/・decisions/・qa/・reviews/・discussions/・migrations-draft/・handoff/（移設残り）・setup-log 3本・architecture.md・database.md・design-tokens.md・farmille-system-overview-ja.md・git-workflow.md・manual-test-review-moderation-2026-06-15.md・README.md（docs 直下のもの。内容が旧構成の索引のため）・refactor-brief-2026-07-12.md
   - `docs/drafts/` は gitignore 済みだが追跡中のファイルが残っていれば `git rm -r`
   - ルート：init.sql・rls.sql・seed.sql・seedgenre.spl・farmille_setup_instructions.md・Makefile
   - `backend/` 全体（スクリプト移設済みを確認してから `git rm -r backend`）
3. **指示ファイルの書換**
   - `AGENTS.md` を全面書き換え：現 `CLAUDE.md` の刷新版冒頭を引き継ぎつつ、旧実装向けの節（型生成の backend 言及・依存セキュリティ監査の backend/uv コマンド・4ロール権限体系・ディレクトリ規約の backend 行・トラブルシューティング）を新体制に合わせて書き直す。含めるべき内容：プロジェクト概要／設計の正は docs/rebuild／技術スタック（Next.js 16・Panda CSS・Supabase・Vercel）／2アカウント制の要約／実装規約（docs/rebuild/03 §8 の7項目を要約転記）／検証コマンド（`cd frontend && pnpm lint && pnpm format:check && pnpm exec tsc --noEmit && pnpm exec vitest run && pnpm build`）／質問すべき条件（docs/rebuild/04 §1・00 §4 逸脱時は停止）
   - `CLAUDE.md` は `@AGENTS.md` の1行だけにする（frontend/ と同じポインタ方式）
4. **05-cleanup.md の整合更新**：旧 migration 28本を「T-01 で tools/migration/legacy/migrations-v1/ へ退避済み」と §3 の記述を実態に合わせて修正
5. **検証**して**コミット**（意味単位で2〜3コミットに分割可。メッセージは conventional commits・日本語可）
