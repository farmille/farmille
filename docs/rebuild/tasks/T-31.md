# T-31 投稿先選択＋レビュー投稿・編集・削除

あなたはフォーム実装に厳密なフルスタックエンジニアです。対象：`/post`・`/materials/[id]/review/new`・レビュー編集/削除。見た目の正はモックの pickMaterial / reviewForm / done 画面（`docs/rebuild/reference/screens/`）。仕様は `docs/rebuild/02-screens.md` §2・§4（項目確定済み）と `01-domain-model.md` §3 reviews。

## 制約

- 触ってよいのは `src/app/post/`・`src/app/materials/[id]/review/`・`src/server/`（reviews 系の mutation 追加）・components/ への追加
- 一般ユーザーのみ投稿可（requireGeneralUser）。server 層で検証し RLS を保険とする
- 写真アップロードは Storage `review-photos` バケット・パス `{user_id}/…`（クライアントから storage.upload 可・DB 行は server 経由）
- 用語 D8。ハードコード禁止

## 実装

1. **`/post`**：資材検索（名前・メーカー部分一致）→選択→固定フッター「使用レポートを書く／レビューを書く」→ 各フォームへ（資材 ID を URL で引き継ぐ）
2. **レビュー投稿 `/materials/[id]/review/new`**：作目（必須・プロフィールの主な作目を初期値に。「プロフィールから自動入力」注記）・星（必須・タップ入力）・本文（必須）・写真（任意・複数・キャプション）・購入場所（任意・select・「公開されません」注記）・対照区の有無（任意・トグル）・農薬表現同意（**必須・未同意は送信不可**）。Server Action で INSERT。既に同資材に自分のレビューがある場合は編集へ誘導
3. **完了分岐**（02 §4-4）：投稿後は資材詳細のレビュー欄アンカーへリダイレクト＋完了トースト（モック done 相当の達成感は簡易でよい）
4. **編集・削除**：自分のレビューに対して。編集はフォーム再利用（初期値埋め）・削除は確認ダイアログ→ DELETE。資材詳細・レビュー全件の自分のカードに編集/削除導線
5. 未ログインでフォーム URL を開いたら `/login?next=…`

## 検証（完了条件）

ゲート一式＋ローカルスタックで実フロー：signup→投稿（写真1枚付き）→資材詳細に反映・集計更新（review_count/avg_rating）→編集→削除→集計が戻る。同意チェック無しで送信不可。出品者アカウントでは投稿導線が出ない＋直接 POST も拒否。375px スクリーンショット。

## 質問すべき条件

- 写真の EXIF・リサイズ等の要件は仕様に無い。最小実装（そのままアップロード・5MB 上限・jpeg/png/webp）とし、逸脱があれば報告

## 最終報告の形式

実装ファイル一覧／検証結果（実フローのログ）／server 追加関数／設計判断。
