# T-41 メーカー申請〜受付完了・招待コード

あなたはフォームと審査フローの実装に丁寧なエンジニアです。対象：`/sellers/apply`・`/sellers/apply/done`。見た目の正はモックの sellerApply 画面（`docs/rebuild/reference/screens/sellerApply.txt`）。仕様は `01-domain-model.md` §3 seller_accounts・§6 と `02-screens.md` §2。

## 定型制約（04 §3・必須）

- 画面は共通 UI キットで組む。ページ側 `styled-system/*` 直接使用はレイアウト調整のみ可
- 不足部品はこのタスク内で発明せず、キット追加を先に行い報告に明記
- 完了報告に**モック sellerApply との2枚並べ**（375px）を添付

## その他の制約

- 触ってよいのは `src/app/sellers/apply/`（新規）・`src/server/`（seller 申請系追加）・components/ への追加
- 申請は**非ログインで可能**（anon INSERT が RLS で許可済み）。Auth ユーザー作成は行わない（承認時に admin が発行＝T-44 の領域）

## 実装

1. **`/sellers/apply`**：メーカー名（法人名）・希望ログイン ID・連絡先メール「公開されません」・担当者名「公開されません」・所在地・主な地域（全国／地方ブロック／都道府県）・公式サイト URL 任意。「Farmille からのご案内で登録される方はこちら」→ 招待コード入力欄の開閉。申請できるのは農業資材メーカーだけと明記し、種別選択は設けない
2. パスワードの扱い：申請時点では Auth ユーザーを作らないため、**パスワードは保存しない**。申請フォームからパスワード欄を外し「承認時にログイン情報をご連絡します」の注記に変える（要件定義と 01 の整合解釈。逸脱として報告に明記）
3. `login_id` の形式検証（合成メールのローカル部として使える形式・重複チェック）・招待コードは seller_accounts.invite_code に照合（存在すれば申請レコードに紐付け）
4. **`/sellers/apply/done`**：受付完了（審査目安3営業日）
5. 申請 status='applied' で INSERT。同一 login_id の再申請はフィールドエラー

## 検証（完了条件）

ゲート一式（pipefail）＋実フロー：申請→ done→ DB に applied 行。login_id 重複エラー。2枚並べスクリーンショット。

## 質問すべき条件

- パスワード非保存の解釈（手順2）に問題があると考える場合は実装前に停止して報告

## 最終報告の形式

実装ファイル一覧／検証結果／キット追加の有無／モックとの意図的差分（2枚並べ付き）。
