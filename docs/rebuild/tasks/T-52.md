# T-52 Sentry・GA4・エラー画面・パフォーマンス確認

あなたは計測と仕上げに丁寧なフロントエンドエンジニアです。

## 定型制約（04 §3・必須）

- 共通 UI キットで組む。不足部品はキット追加が先。エラー画面はモックに無いため単独スクリーンショットで可

## 制約

- 触ってよいのは Sentry/GA 設定ファイル・`src/app/` の error/not-found/loading・`src/lib/analytics/`（新規）・`next.config.ts`・画像最適化に必要な箇所
- 計測は環境変数が無ければ**何も送らない**（silent fallback ではなく「未設定なら無効」を明示的に分岐し、起動は失敗させない。NEXT_PUBLIC_GA_MEASUREMENT_ID・NEXT_PUBLIC_SENTRY_DSN は任意設定）

## 実装

1. **Sentry**：`@sentry/nextjs` の現行構成を Turbopack 対応の推奨形へ更新（ビルド時の DEPRECATION 警告2種を解消：disableLogger・automaticVercelMonitors）。サーバー／クライアント両方の捕捉・PII 送信なし
2. **GA4**：`@next/third-parties` の GoogleAnalytics を layout に条件付き設置。主要イベント（レビュー投稿・使用レポート提出・検索実行・保存）を `lib/analytics/` の型付きヘルパで送信
3. **エラー画面**：`error.tsx`（既存があれば文言・デザイン統一）・`not-found.tsx`・主要セグメントの `loading.tsx`（スケルトンは簡素で可）
4. **パフォーマンス**：`next build` の route サイズ表を確認し、ファーストビュー画像（資材カード・hero）の `next/image` 化漏れ・`priority` 指定・`sizes` を整える。admin の `<img>` 警告19件を `next/image` へ置換（lint 警告ゼロに）
5. Lighthouse（モバイル・ホーム＋資材詳細）を実行して LCP・CLS を記録（数値目標は設けない。実測の記録まで）

## 検証（完了条件）

ゲート一式（pipefail・lint 警告 no-img-element 0件）＋ 375px でエラー画面・404 のスクリーンショット＋ Lighthouse 結果の要約。GA/Sentry 未設定時にコンソールエラーが出ないこと。

## 質問すべき条件

- Sentry の Turbopack 対応で next.config の構造変更が必要なら、変更内容を報告に明記（動作が変わる場合は停止）

## 最終報告の形式

変更ファイル一覧／検証結果／Lighthouse 実測値／解消した警告の数。
