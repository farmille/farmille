# T-45 admin：通報処理・使用レポート編集局（＋却下理由 migration）

あなたは運用ワークフローの実装に丁寧なエンジニアです。対象：`/admin/reports`・`/admin/usage-reports`。仕様は `01-domain-model.md` §3（content_reports・usage_reports）・§6（状態遷移）。admin UI は D4（機能優先・キット部品）。T-44 の `withAdmin()`・admin-shell・DataTable を再利用すること。

## 制約

- 触ってよいのは `src/app/admin/reports/`・`src/app/admin/usage-reports/`（新規）・`src/server/admin/`（追加）・`supabase/migrations/`（下記1本のみ新規）・`src/types/database.types.ts`（gen 再生成）
- 全操作 requireAdmin（AAL2）。T-44 の guard 経由

## 実装

1. **migration（1本）**：`seller_accounts.rejected_reason text NULL` を追加（T-44 の提案採用）。適用後 `gen types --local` で types 再生成。T-44 の却下フォームに理由入力欄を追加して保存（`src/app/admin/sellers/` の該当フォームのみ変更可）
2. **`/admin/reports`**：通報一覧（open／resolved／dismissed のフィルタ・対象コンテンツへのリンク・通報者は内部情報として表示）→ 処理：**対象の非公開化**（review→status='hidden'・usage_report→'declined' 相当の非公開・article→'draft' 化・profile は対象ユーザーページへのリンク提示のみ＝v1 はアカウント凍結機能を持たないため運用対応）＋ resolved／却下（dismissed）。resolved_by・resolved_at 記録
3. **`/admin/usage-reports`（編集局）**：pending 一覧→詳細（全セクション・メディア・収穫調査の閲覧）→ **本文・タイトルの調整編集**（editor_note に内部メモ）→ **公開**（status='published'・published_at）／**差し戻し**（'declined'＋editor_note。投稿者のマイページで「差し戻し」表示になることを確認）。draft は一覧に出さない
4. `/admin` トップの件数カードから両画面への導線を接続（T-44 が件数のみ実装済み）

## 検証（完了条件）

ゲート一式（pipefail）＋ migration の `db reset` 完走＋実フロー：T-34 で入れた通報を resolve（レビュー非公開→公開側から消える）。pending 使用レポートを編集→公開→ /reports/[id] で閲覧可・投稿者マイページで published 表示。差し戻し→マイページで確認。却下理由の保存・表示。スクリーンショット添付。
