# T-32 使用レポート投稿フォーム（6セクション・下書き・提出）

あなたは複雑なフォーム状態管理に強いエンジニアです。**モック最大のフォーム**。対象：`/materials/[id]/report/new`（＋下書き再開）。見た目と構成の正はモックの reportForm 画面（`docs/rebuild/reference/screens/reportForm.txt`＝約14KB の最重要参照・モック HTML の該当実装 initCropPicker/renderStageList/makeCalendar 等も grep して挙動を写す）。仕様は `02-screens.md` §2 と `01-domain-model.md` §3 usage_reports（draft→pending のワークフロー）。

## 制約

- 触ってよいのは `src/app/materials/[id]/report/`・`src/server/`（usage_reports mutation 追加）・components/ への追加（CalendarPicker 等のフォーム部品は components/form/ へ）
- 一般ユーザーのみ。メディアは Storage `report-media`・パス `{user_id}/…`
- 状態管理はクライアント（"use client"）でよいが、**送信・下書き保存は Server Action**。動的スタイル禁止（variant 列挙）

## 実装（モック reportForm の構成に忠実に）

1. 対象資材の自動表示（URL の id から。pickMaterial からの導線と整合）
2. 作目選択（必須・タグ検索式・複数可→**作物ごとタブ**で以降のセクションを切替。タブ切替時に入力状態を保持——モックの snapCropState/applyCropState 相当）
3. セクション[1] 観察した変化（必須）・マイナス点（任意）
4. セクション[2] 条件詳細：使用目的タグ（必須・複数・4分類22タグ相当は tags シードの purpose 相当が無ければ**固定配列で実装し報告**）＋補足／地域（必須・47都道府県）／圃場名・品種（任意）／定植時期（任意・カレンダー単一日）／栽培区分（必須・ラジオ3択）＋栽培特徴タグ（任意・区分依存）／生育ステージ（必須・作物群依存の選択。モック STAGE_SETS を定数化）／気候詳細（任意トグル）
5. 使い方：処理日（必須・カレンダー複数日）／使用方法（必須・ラジオ4択→分岐パネル）／対照区詳細（任意トグル・4項目）／定量データ（任意トグル：指標名・対照区値・処理区値・単位 → usage_report_metrics）
6. セクション[3] 写真・動画（任意・複数・表示先 select＋キャプション → usage_report_media）
7. セクション[4] まとめ（必須）＋農薬表現同意（必須）
8. **下書き保存**（status=draft・何度でも上書き）と**提出**（draft→pending。提出後は本人編集不可＝閲覧のみ）。提出完了画面は「編集部で確認後に公開されます」（02 §4-4）
9. 下書きがある資材のフォームを開いたら復元。バリデーションは必須欠落をフィールド単位で表示（NOT NULL の observed_change/summary は draft 保存時は空文字で保存＝01 の申し送りどおり）

## 検証（完了条件）

ゲート一式＋実フロー：下書き保存→リロード復元→提出→pending になり本人は編集不可・公開側に出ない（/reports/[id] が notFound）→（psql で status='published' に更新）→公開側に表示される。作物2つ選択でタブ状態が独立保持される。375px スクリーンショット（フォーム上部・カレンダー・定量データ・完了画面）。

## 質問すべき条件

- モックの挙動が読み取れない箇所は最も単純な解釈で実装し、報告に列挙（勝手に機能を増やさない）

## 最終報告の形式

実装ファイル一覧／検証結果／状態管理の設計（タブ・下書き）要約／固定配列にした語彙一覧。
