# T-04 CI（GitHub Actions）＋ M0 ドキュメント整合

あなたは CI 構築の経験豊富なエンジニアです。アプリの品質ゲートを GitHub Actions 化し、あわせて M0 で見つかったドキュメント不整合を修正する。

## 制約

- 触ってよいのは `.github/`（新規）・ルート `README.md`・`docs/rebuild/03-architecture.md`（§7 の1箇所）・`docs/rebuild/05-cleanup.md`（§1 の1箇所）・`.gitignore`（コメント2行）のみ
- アプリのコード・設定は変更しない（CI から呼ぶだけ）
- secrets を要求する step（デプロイ等）は作らない。CI は検証のみ

## 手順

1. `.github/workflows/ci.yml`：push（全ブランチ）と PR で発火。Node 24・pnpm 11（package.json の packageManager に合わせる）・pnpm cache。steps：`pnpm install --frozen-lockfile` → `pnpm lint` → `pnpm format:check` → `pnpm exec tsc --noEmit` → `pnpm exec vitest run` → `pnpm build`。working-directory はリポジトリルート。`prepare` で panda codegen が走る前提を確認し、走らない場合は明示 step を足す
2. `.github/workflows/migrations.yml`：`supabase/migrations/**` に差分がある PR で、Docker の supabase local に対し `npx supabase db reset` が通ることを検証（`supabase/config.toml` が無い場合はこのワークフローを when 条件でスキップ）
3. ルート `README.md` を全面書き換え：プロジェクト1行説明／設計の正は docs/rebuild/／セットアップ（pnpm install・.env.local・pnpm dev）／検証コマンド／ディレクトリ構成（docs/rebuild/03 §7）。Railway・FastAPI・make の記述を残さない
4. ドキュメント整合の微修正：
   - `docs/rebuild/03-architecture.md` §7 の「旧28本」→「旧27本（tools/migration/legacy/migrations-v1/ へ退避済み）」
   - `docs/rebuild/05-cleanup.md` §1 の backend/scripts 列挙（9本）に `prod_import_2026_06_09.py`・`prod_import_sources_2026-06-09.py` を追記して11本の実態に合わせる
   - `.gitignore` 内コメントの `backend/scripts/excel_to_seed_sql.py` 参照を `tools/migration/legacy/excel_to_seed_sql.py` に修正
   - `src/lib/supabase/paths.ts` 冒頭コメントの `docs/specs/...` 参照（削除済みドキュメント）を削除 — ※これだけアプリ本体に触るが1コメントのみ許可
5. 検証・コミット

## 検証（完了条件）

- `act` は使わなくてよい。ワークフロー YAML を `node -e` 等で構文チェックし、steps のコマンドをローカルで同順に実行して全通過することを確認
- `git grep -n "Railway\|FastAPI" README.md` が 0 件

## 最終報告の形式

作成・修正したファイル一覧／ローカルでの steps 実行結果／YAML の設計判断（cache・トリガー条件）。
