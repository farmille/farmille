## 1. なぜ刷新するか

要件定義 v1（2026-07-06）で製品の骨格が変わった。旧実装（4ロール制・Tailwind・FastAPI BFF）は試作として役目を終え、後方互換を持たずに作り直す。

- **アカウント体系の転換**：農家／メーカー／JA／専門家の4ロール制を廃止し、「一般ユーザー（匿名・ハンドルネーム）」と「出品者（実名・法人）」の2アカウント制へ。「何者か」はプロフィール属性で表現し、権限とは分離する
- **コンテンツモデルの転換**：レビュー（軽量・星＋短文）と使用レポート（構造化長文・収穫調査・編集局ワークフロー）を別オブジェクトとして立てる。資材は「情報の倉庫」としてすべての投稿が集まるハブになり、一次情報層（メーカー編集可）と分類・検索層（Farmille 所有）の2層に所有権が分かれる
- **フロントの品質基準**：スマホ版モックアップ（19画面）を目標品質とする。スマホ表示が最優先、レスポンシブは従。旧方針にあった「UI は素早さ優先で雑に作る」という考え方は採らない（D13）

## 3. スコープ

### Phase 1（今回作るもの）

- 資材：検索（タグ AND/OR）・詳細（2層構造・エビデンス・レビュー・使用レポート埋め込み）・レビュー全件一覧
- レビュー：投稿・編集・削除・参考になった・通報
- 使用レポート：投稿（6セクション＋収穫調査）・編集局ワークフロー（draft → pending → published）・記事形式の閲覧
- 検討リスト（資材の保存）・資材比較（検討リスト起点の簡易比較表）
- 記事：出品者による投稿・資材への複数紐づけ・資材ページでの関連記事表示
- アカウント：一般登録／ログイン、出品者申請〜審査〜共有 ID ログイン、プロフィール編集
- 出品者ダッシュボード：自社資材の claim・一次情報編集・エビデンス管理・分類変更申請・記事管理
- 運営管理（最小 UI）：出品者審査・資材登録／claim 承認・タグ管理・通報処理・使用レポート編集局
- 非ログイン閲覧：全コンテンツ公開（投稿・参考になった・保存のみ要ログイン）

### Phase 2（スキーマだけ先行設計、UI は作らない）

- Q&A（質問・回答・公式回答。出品者の「公式回答」機能は Q&A の一部なので Phase 2）
- フィード（縦スワイプ閲覧。モック上も導線が無い孤立画面であり、除外と整合）
- フォロー・通知、出品者のメンバー個別ログイン、記事カテゴリ／タグ、モニター（お試し）制度、可視 Tier

### 作らないもの（v1 で明確に捨てる）

- 旧実装の全機能・全画面（資材マスタのデータのみ移行）
- レビューへの出品者返信（要件定義の議論ポイント5。Q&A との完全分離方針）
- 収集しない項目：栽培面積・年齢層・経営主体・就農形態

## 4. 確定済みの意思決定（2026-07-26 承認）

| # | 決定 |
|---|---|
| D1 | DB は同一 Supabase プロジェクトでスキーマをゼロから刷新。資材マスタ294件（資材・画像・出典・メーカー名・施用レシピ）のみ移行スクリプトで新スキーマへ載せ替え。ユーザー・レビュー等の旧データは破棄 |
| D2 | **バックエンドは Next.js に集約する。FastAPI・Cloud Run・Python スタックは廃止**（03 §2）。Route Handlers ＋ Server Components が第一防御、RLS が第二防御 |
| D3 | v1 スコープは「Q&A・フィード以外すべて Phase 1」。記事投稿（出品者）も Phase 1。公式回答は Q&A の一部として Phase 2 |
| D4 | 運営管理は最小 admin UI を v1 で新規作成（デザイン品質はモック基準の対象外） |
| D5 | 所属団体（全青協・JA 等）はモック準拠：マイページ・公開プロフィールにバッジ表示（任意項目）。投稿カードには出さない |
| D6 | 非ログイン閲覧は全公開。投稿・参考になった・保存のみ要ログイン（SEO 優先） |
| D7 | 購入場所は投稿フォームで任意収集し、カードには表示しない（内部データ・信頼スコア用） |
| D8 | UI 用語は「レビュー」「使用レポート」に統一（モックの「口コミ」「使用結果レポート」表記は置換する）。比較栽培の用語は「対照区」に統一 |
| D9 | エラーレスポンスは `{ok: false, error: "<code>"}` 形式に統一 |
| D10 | Panda CSS へ移行（Tailwind 廃止）。lint は oxlint 主体、format は oxfmt（03 §4） |
| D11 | 不要ドキュメント・旧コードは削除する（05 参照）。ADR 体系は本設計ドキュメント群で置き換え、以後の意思決定は docs/rebuild/ に追記する |
| D12 | **ダークモードは実装しない。ライトテーマのみ**（モックにはダーク実装があるが v1 では採用しない）。トークン定義にも `_dark` 条件を持ち込まない |
| D13 | **フロントエンドにも品質規約を適用する。**「UI は素早さ優先で雑に作ってよい」という旧方針は廃止し、データ層と同じ基準（型安全・fail fast・トークン経由・実画面での検証）で作る（03 §8） |
| D14 | 実装を委譲するモデルは Claude Opus 5／GPT-5.6 Sol／Cursor Grok 4.5 High Fast の3系統。Opus 5 と Sol は **reasoning effort を既定で xhigh** にする（04 §3） |
