# 一般会員登録

## 登録の順序

1. `/signup`と`/signup/general`ではメールアドレスだけを入力する。上部にログイン、下部に「メーカーの方はこちら」を置く。
2. 認証メール送信後は同じ画面でメール確認を案内し、再送を受け付ける。プロフィール入力へは進めない。
3. メールのリンクから`/signup/complete`へ進む。認証したメールアドレスを固定表示し、ニックネーム、本名、電話番号、立場、住所、パスワードを入力する。
4. 「利用規約・プライバシーポリシーに同意する」を必須とし、その下のスクロールできる枠に既存の総合利用規約とプライバシーポリシーを表示する。
5. 登録情報を保存して登録完了メールを送り、`/signup/done`にログイン導線を表示する。登録中・登録直後には通常のログインセッションを発行しない。会員権限を与えるときに、初回ログインの案内を待つ印も付ける（`onboarding-tour-SPEC.md`）。

## 本人確認と保存

- 第1段階のメールアドレスはSupabase Authに保持する。ブラウザを閉じてもメールリンクから続行できる。
- リンクの有効期限はSupabaseの`otp_expiry`に従い1時間とする。使用済み・期限切れリンクは再送案内へ戻す。
- メール確認用の本人証明は署名付きHttpOnly cookieとして`/signup`内に限定し、1時間有効とする。通常の認証cookieとは分離する。
- 第2段階の直接アクセス・証明の改ざん・未確認メールによる保存を拒否する。保存先のメールアドレスとIDはサーバー側で証明から取得する。
- 会員種別が設定済みのアカウントを再登録で変更しない。同じ本人の重複送信でプロフィールを上書きしない。
- 保存が失敗した場合は、その試行で作成したプロフィール・連絡先・通知待ちだけを取り消し、メール確認済みのAuthユーザーは残す。
- 公開情報は`profiles`、非公開連絡先は`profile_contact_details`に保存する。郵便番号は画面で`123-4567`、保存時は7桁とする。
- 完了メールは「【Farmille】会員登録が完了しました」とし、ログイン画面へのリンクを含める。認証メールは「【Farmille】メールアドレスの確認（会員登録はまだ完了していません）」とし、登録情報入力へ進むリンクと期限（1時間）、期限切れ時の再手続き先（`/signup`）を含める。
- 認証メール・完了メール・パスワード再設定メール・企業会員の案内メールの件名と本文は `src/lib/account-email.ts` の1か所に置き、件名の頭を「【Farmille】」、名乗りを「Farmille運営事務局」、結びを送信専用の注記・問い合わせ先・運営会社のフッターでそろえる。

## 入力と表示

- 非公開項目は目を閉じたアイコンで示し、読み上げでは「公開されません」と伝える。公開項目はアイコンと「公開」を表示する。
- 住所の市区町村と番地は「市区町村・番地」の1欄とし、非公開連絡先の1列に保存する。都道府県は公開し、郵便番号、市区町村・番地、建物名・部屋番号は公開しない。市区町村・番地は必須、建物名・部屋番号は任意とする。
- 郵便番号による都道府県・市区町村・町名の補完には、jposta が同梱する日本郵便の郵便番号データをサーバー上で検索し、郵便番号を外部へ送らない。市区町村と町名が1つに決まるときは、市区町村の直後に町名を空白なしで「市区町村・番地」へ入れる。番地の数字は自動補完しない。「以下に掲載がない場合」と「番地がくる場合」の町名は入れない。欄が空か、直前の自動入力のままのときだけ上書きする。市区町村が複数のときは自動入力しない。市区町村は1つで町名が複数のときは都道府県だけを入れ、市区町村・番地は手入力する。
- 登録時には作目・所属を要求せず、登録後に設定を案内する。所属は既存のプロフィール編集で設定する。空欄の候補一覧を表示せず、入力に一致する未選択候補を表示する。選択済みの所属は削除できる。

## 登録情報の変更

- 一般会員は`/account`の「設定」で、登録時に入力した非公開の情報と都道府県を変更する。未ログインは`/login?next=%2Faccount`へ送る。運営は`/account/password`と同じく2要素認証を済ませてから開け、個人プロフィールが無ければ`/me/setup`へ送る。メーカーは`/dashboard`へ送る。
- 画面の上に「この画面の情報はサイトに公開されません。都道府県は、プロフィールの地域として公開されます。」を表示する。
- 「氏名・住所・電話」の区で、本名（姓・名）、電話番号（任意）、郵便番号、都道府県、市区町村・番地、建物名・部屋番号（任意）を変更する。入力欄・検証・文言・郵便番号からの住所補完は`/signup/complete`と同じものを使う。
- 保存先は都道府県が`profiles.prefecture_code`、ほかは`profile_contact_details`とし、ログイン中の本人の行だけを読み書きする。連絡先の行が無いアカウントでも画面を開け、保存すると行を作る。保存できたら「登録情報を保存しました。」を表示する。送信後にエラーがあれば、最初のエラーの欄へ移動する。
- 「ログインとセキュリティ」の区に「パスワードを変更」（`/account/password`）と「パスキーを管理」（`/account/passkeys`）を置く。一般会員が両画面から戻る先は`/account`とし、リンク名は「設定に戻る」とする。
- アカウントメニュー（PC・スマホ）とマイページ下のボタンでは、パスワードとパスキーの項目を置かず、「設定」（`/account`）1つにまとめる。メーカーのダッシュボードと運営管理の入口と戻り先は変えない。
- メールアドレス、立場の変更と退会は扱わない。都道府県はプロフィール編集（`/me/edit`）では変更しない。

## 検証

メール送信・再送・リンク・第2段階のアクセス制御・登録完了・未ログイン・通常ログインを専用ローカルSupabaseとMailpitで確認する。PCと375pxの画面を操作し、変更した画面の動画をPRに添付する。実メールの受信、迷惑メールの分類、本番SMTPの差出人は運用環境で別途確認する。
