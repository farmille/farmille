# メーカーによる資材ページ編集

## スコープ

メーカーが自社の資材ページを執筆し、運営は所有権確認、公開前の表現確認、公開後の監査を行う。初期ページは運営が公開資料から作成する。メーカー申請、掲載、編集は無料とする。申請の対応日数は約束しない。

画像・資料を含む公開変更に表現確認を適用する。メーカーが入力した項目には記入元を示し、公式認証や効果保証を示すマークは付けない。

## 対象と関係

| 対象 | 性質と状態 | 操作と関係 |
| --- | --- | --- |
| メーカー | 会社紹介、ロゴ、リンク、連絡先、アカウント状態 | 1メーカーが複数資材の編集権を持つ。連絡先は非公開 |
| 資材ページ | 製品名、公開版、公開状態 | 製品を選び、原稿編集、プレビュー、履歴へ進む。製品名変更は運営への連絡 |
| 編集権 | 対象資材、メーカー、書類の保管参照、確認者、付与日、失効日 | 運営が書類に基づき資材単位で付与・解除する。メーカー名の一致は候補抽出にのみ使う |
| 原稿版 | 本文、複数画像、5分類の資料、試験情報、方法と詳細、時期、作用機作、登録認証、関係会社、分類 | 下書き、表現確認中、公開済み、修正待ち。確認した版をそのまま公開する |
| 確認・監査記録 | 対象版、運営担当者、日時、指摘 | 内容を代理執筆せず、公開または理由付きの修正依頼を行う |

保存とプレビューは同じ原稿の操作であり、別の申請オブジェクトをメーカーに意識させない。画像と資料は原稿に付随し、単独の管理画面へ分断しない。履歴は日時と内容を比較する意味があるため版として保持する。

## 登録と編集権

1. メーカーが会社情報と担当者を送信する。希望資材は備考に自由記入する。
2. 運営がアカウントを発行する。ログインID、パスワード設定案内、資材候補一覧、編集権申込書類を手動メールで送る。
3. メーカーが候補の正誤と追加掲載希望を記入し、書類を返送する。
4. 運営が書類の保管参照を記録し、対象資材ごとに編集権を付与する。
5. メーカーが原稿を編集し、表現確認後に公開する。

メール送信と書類の署名・返送は外部業務とする。システムは証跡の参照と付与履歴を保持し、書類の法的有効性を自動判定しない。アカウント発行と編集権付与を同時に行わない。

## ビューと操作

メーカーの入口は製品情報とメーカープロフィール。製品一覧で名前と状態を確認し、同じ資材の編集・プレビュー・履歴を行き来する。空の場合は編集権の確認待ちであることと連絡先を示す。

製品エディタは公開ページと同じ順序で、製品画像、製品説明、施用タイミング、リンク・資料（概要／使用上の注意／技術・作用機作／公的試験結果／その他の試験結果）、施用方法と詳細、製品詳細、登録・認証、関係会社を置く。資料と画像は追加・削除でき、画像は順序も変更できる。公開状態と原稿状態を別に示す。

資料の分類はメーカーが選択する。初めて編集する既存資料は分類未選択で表示し、下書きには残せるが、分類を選ぶまで表現確認に送れない。試験結果には題名、概要、実施機関が必須で、作目、実施年、ページ数は任意とする。公開画面では試験結果をカードで表示する。同じURLの複数行は下書きに残し、送信時に重複を拒否する。

登録・認証は農薬登録、肥料登録・届出、土壌改良資材を複数選択できる。各区分の事業者名は送信時に必須、効果・特徴は任意とし、空欄は「−」と表示する。従来の自由入力の認証も保持する。関係会社は会社名を並べ、役割や編集権を付与しない。明示的に会社をすべて外した原稿は、プレビューと公開画面の両方で「−」と表示する。

登録情報と関係会社は原稿版に属する子テーブルへ保存する。試験情報は資料行に保持する。保存と承認の両方で公開条件を検証する。旧形式の保存は、新形式の保存履歴がない資材に限って受け付ける。`content_contract` は保存形式を識別し、新形式のデータを旧画面から失わないようにする。

資材ページ上部のリンクと名称は、編集権を持つ代表メーカーの公開情報から表示する。メーカーが未登録または凍結中なら、資材に登録された会社名をリンクなしで表示する。登録事業者や関係会社の編集は、この代表メーカーや編集権に影響しない。

メーカープロフィールは会社紹介、ロゴ、リンクを編集する。同じ原稿を保存しプレビューできる。アカウントの連絡先と公開プロフィールを区別する。

運営はメーカー詳細で候補資材と書類参照を確認し、資材単位の編集権を扱う。表現確認一覧から原稿版を開き、公開版との差分とプレビューを確認して公開または修正依頼を行う。公開後の監査は同じ資材から記録する。

PCは資材選択と原稿の文脈を同時表示し、SPは同じ順序で縦に配置する。未保存の編集をプレビューで失わない。保存エラー時は入力を保持する。確認中の版は変更せず、取り下げて編集を再開する。権限の解除後は保存・確認送信・公開を拒否する。

## 公開と権限の境界

- 下書きと確認中の内容は匿名閲覧者へ出さない。画像も確認前は非公開で扱う。
- 公開はトランザクション単位で行い、画像や資料だけが先に変わらない。
- 公開版の更新競合を検知し、別の更新を上書きしない。
- 資材名の一致による自動claimと、運営のアカウント確認時の一括claimを廃止する。
- 既存の紐づけも書類確認まで編集を停止する。過去の紐づけは監査用に保存し、公開ページと口コミは維持する。従来の未処理申請は取り下げとして履歴を残す。
- メーカーの入力済み表示は執筆・公開の状態であり、公式認証や効果保証を意味しない。

## 検証経路

| タスク | 経路と期待結果 |
| --- | --- |
| 登録 | 案内→会社と担当者の申請→運営の案内。資材の権限は未付与 |
| 所有権確認 | メーカー詳細→候補→書類参照→対象資材への編集権付与。別資材に波及しない |
| 執筆 | 製品一覧→資材→編集→下書き→再読み込み。入力が保持される |
| 公開確認 | 同じ原稿→プレビュー→確認送信→運営が公開。公開前は旧内容を維持 |
| 修正 | 原稿履歴→指摘→編集再開→再送信。指摘と過去版が残る |
| 権限外 | 別メーカーが資材IDや原稿IDを指定しても閲覧・変更できない |
| 監査 | 公開資材→監査記録→修正依頼または非公開。履歴を保持 |

## 設計検証

資材そのものを選んで編集すること、同じ資材に公開状態と原稿状態を示すこと、関連するメーカー・編集権・版を辿れることを設計の基準とする。登録の順序固定は権限付与前の確認に限定する。編集権を移行した資材やメーカー原稿の公開履歴がある資材は、運営の初期登録用フォームから上書きしない。

## ローカル検証結果

2026年9月15日から16日に、独立したローカルSupabaseと開発サーバーで確認した。以下はローカル環境の検証結果であり、本番環境の検証と案内メールの実送信は含まない。

- DBテストは57件成功した。書類参照の必須化、未確認・別メーカー・権限取消後の編集拒否、下書きの非公開、更新競合、プロフィール公開、画像の公開時点と履歴保持、投稿保存の本人限定アクセスを確認した。
- アプリの単体テストは171件成功した。既存の接続環境を要する統合テスト2件はskipとなった。
- lint、型チェック、フォーマット検査、Storyの網羅性検査、Next.jsビルドが成功した。Storybookビルドも成功したが、既存コンポーネントを含むクライアントディレクティブとバンドルサイズの警告が出た。
- 実画面では、書類未確認時の編集拒否、メーカーの下書き保存と再読み込み、画像アップロード、3群の資料入力、プレビュー、表現確認への送信を確認した。運営の2要素認証を経て原稿を公開し、公開ページの本文と画像が更新された。
- 公開前の画像は匿名アクセスで404、表現確認後は200となった。メーカーが非公開にすると再び404となり、原稿と投稿履歴は保持された。
- 会社紹介は画面から下書き保存、再読み込み、プレビュー、確認送信を行った。公開処理はDB関数と運営の確認画面の両方で実行し、公開プロフィールへの反映を確認した。会社紹介だけが確認待ちの場合も一覧に表示され、空一覧の案内は表示されなかった。
- SPは375px、PCは1440pxで確認した。SPの原稿プレビューでは横方向のはみ出しがなかった。
- 依存監査で除外対象となっているimage-sizeのhigh脆弱性2件は、既存パッチの検証が成功した。今回、新たな除外は追加していない。依存ライブラリの更新候補は別途残っている。

## リリース時の確認

スキーマ変更はアプリ変更と別PRに分ける。既存の紐づけは`material_editor_legacy_links`に保持されるが、そのまま編集権にはならない。既存の確認待ち変更申請は取消状態として履歴を残す。

本番で既存資材数・投稿数・紐づけ数を確認し、migration適用後に公開資材と投稿が維持され、書類未確認の編集権が残っていないことを確認する。型を再生成し、`supabase db diff --linked`で差分がないことを確認する。本番のDB適用と画面操作は、このローカル検証結果には含めない。
