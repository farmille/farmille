# 第 1 部 — MVP 起点の論点（A〜H）

## A. コミュニティ機能 `/community` ⚠️

### A.0 機能サマリ
農家・JA 普及員・研究者が地域別／目的別のグループで知見を共有するフォーラム機能。

### A.1 MVP 観測 / 現状
- MVP に 4 グループのフォーラム形式が実装されている
- 投稿項目: タイトル、投稿者（例「北海道 佐々木農園」）、日時、投稿数（3〜4件）
- リアクション UI（いいね・コメント）は未実装、投稿フォームも MVP では見えない（読み取り専用）
- 既存 PRD §6 では「v1 やらない」（リアルタイム更新系列）

### A.2 ユーザーとゴール
- **農家**: 地域や作目が近い他農家の使い方を質問・共有して、自分の圃場に応用したい
- **JA 普及員**: 組合員に伝える前に他地域の事例を確認したい
- **研究者**: 現場の声をスキャンし、研究シードを発見したい

### A.3 ユーザーストーリー
- 農家として、自分の地域グループに参加して "今この時期どんな対策をしてるか" 質問したい。集合知が一人の判断より信頼できるから。
- 農家として、他人の投稿を読むだけで参加できる。いきなり投稿はハードルが高いから。
- JA 普及員として、自分の管轄地域グループの動向を読みたい。組合員提案のエビデンスになるから。
- 運営として、不適切投稿を削除できる。荒らし対策とコンテンツ品質維持のため。

### A.4 画面要素
- `/community` グループ一覧
  - グループカード: アイコン、名称、説明、参加人数、最新投稿日時、投稿数
  - 「グループに参加」ボタン（ログイン必須）
- `/community/{slug}` グループ詳細
  - 投稿一覧（タイトル、投稿者、日時、コメント数）
  - 「新規投稿」ボタン（参加者のみ）
  - 投稿フォーム: タイトル、本文、画像最大 3 枚
- `/community/{slug}/posts/{id}` 投稿詳細
  - 投稿本文 + コメント一覧 + コメント投稿フォーム
  - 通報ボタン（v1 に含むか要決定）

### A.5 主要データ項目
- `community_groups`: id, name, slug, description, owner_user_id, created_at
- `community_group_members`: group_id, user_id, joined_at
- `community_posts`: id, group_id, author_user_id, title, body, created_at
- `community_comments`: id, post_id, author_user_id, body, created_at
- `community_post_images`: id, post_id, url, position
- （通報を v1 含めるなら）`community_reports`: id, target_type, target_id, reporter_user_id, reason, created_at

### A.6 ロール権限
- 閲覧: 全ユーザー（未ログイン含む）
- 参加: ログイン済み（farmer / ja_staff / researcher / maker）
- 投稿: 参加者のみ（**maker も投稿可とするか要決定**）
- 削除: 投稿者本人 + 運営
- グループ作成: v1 は運営のみ（初期 4 グループから始める）

### A.7 v1 スコープ外（推奨）
- いいね / リアクション
- フォロー / メンション
- 通知（メール・push）
- リアルタイム更新（再読込で取得）
- 投稿の編集（v1 は新規 / 削除のみ）
- グループの自由作成（運営承認制は v1.5+）

### A.8 Claude 案（叩き）
**推奨: v1 で読み取り専用 + ログイン後投稿可、モデレーションは運営手動（SQL）。v1.5 で通報ボタン追加。**

理由:
- MVP に既にあり、IA 上の存在感が大きい。完全に外すと「機能後退」感が出る
- 業務フロー（モデレーション、荒らし対策）は重いが、投稿数が少ないうちは運営手動で耐える
- リアルタイム更新は PRD §6 を尊重して v1.5 以降

## B. Farmille AI 🔥（2026-06 末納期）

### B.0 機能サマリ
LLM を活用してレビューを横断検索・要約・推薦する AI 機能。**v1 入り、6 月末納期確定**。

### B.1 MVP 観測 / 現状
- MVP のグローバルナビに「Farmille AI」項目あり、リンク先は未確認
- 既存 PRD §6 では「v1 やらない、v2.5 候補」だったが、ビズ要望で v1 入りに変更
- LLM プロバイダ・データソース・コスト構造は未確定

### B.2 ユーザーとゴール
- **農家**: 自分の圃場条件を自然文で入力して、合いそうな資材を AI に提案してほしい
- **農家**: 大量のレビューを読まずに「○○の効果がある資材」を一発で見つけたい
- **メーカー**: 自社資材へのレビューを AI で要約して、改善ヒントを得たい（v1.5+）
- **研究者**: レビュー全体から特定パターン（例: "猛暑時の効果"）を抽出したい

### B.3 ユーザーストーリー（叩き、機能仕様は議論で確定）
- 農家として、検索バーに「夏の高温下で水稲の収量を保ちたい」と入力すると、関連レビューと推奨資材が返る
- 農家として、製品詳細ページで「このレビューの要点」を AI 要約で読める。レビュー全件読むのは時間がかかるから
- 未ログインユーザーとして、月 N 回まで無料で使える。サインアップ動機にしたい

### B.4 画面要素（候補、議論で絞る）
**選択肢 1: 独立ページ（チャット型）**
- `/ai` チャット UI（ChatGPT 風）
- 入力欄、チャット履歴、出典レビューへのリンク

**選択肢 2: 既存ページ埋め込み**
- 資材一覧の検索バーで自然文入力可能
- 資材詳細にレビュー要約セクション

**選択肢 3: ハイブリッド**
- 独立ページ + 埋め込み

### B.5 主要データ項目
- 既存テーブル（reviews, products）を読み取り
- 新規: `ai_query_logs`: id, user_id (nullable), query, response_summary, used_review_ids, cost_usd, latency_ms, created_at
- LLM ベクター埋め込みを使うなら: `review_embeddings`（pgvector）

### B.6 ロール権限
- 閲覧 / 利用: 全ユーザー（未ログイン含む、ただしレート制限あり）
- 利用上限: 未ログイン < ログイン済み < 有料（v1.5+）

### B.7 v1 スコープ外（推奨）
- マルチターン会話の長期記憶
- メーカー向け詳細分析（v1.5+）
- 学習データへのフィードバックループ
- 自動レビュー要約のリアルタイム生成（バッチでよい）
- 完全な多言語対応（日本語のみで OK）

### B.8 Claude 案（叩き）
**推奨: 機能は「自然文検索 + 製品レビュー要約」の 2 つに絞る。LLM は Anthropic Claude（haiku / sonnet）。**

理由:
- 6 月末納期 = 約 2 ヶ月。スコープを絞らないと間に合わない
- "自然文検索" は埋め込み検索（pgvector）+ LLM 整形で実現、コストが読める
- "レビュー要約" は事前バッチ処理 + 製品詳細ページに静的表示。ユーザーの待ち時間ゼロ
- Anthropic 採用理由: 日本語精度、価格、ハルシネーション対策ツール

**コスト試算（仮）**: 月間 1000 query × 平均 5000 トークン × Sonnet $3/Mtok ≒ $15/月

**ハルシネーション対策**: 必ず出典レビュー ID を返す、出典なしの主張は表示しない。

## C. ランキング `/ranking` `/leaderboard` ⚠️

### C.0 機能サマリ
レビュー★評価平均などの軸で BS 資材をランキング表示する機能。

### C.1 MVP 観測 / 現状
- MVP `/ranking` で BS 資材高評価 TOP 10 を実装、★評価平均軸
- 項目: 順位、画像、メーカー名、製品名、★評価、レビュー件数、含有成分タグ、効果タグ、概要
- フッターに `/leaderboard`（人気ランキング）リンクあり、`/ranking` との差分不明
- 既存 PRD: 未記載

### C.2 ユーザーとゴール
- **農家**: 何を選べばいいか分からないとき、まず人気・高評価の資材から見たい
- **メーカー**: 自社資材がランキングに載るとブランド価値が上がるので登録動機になる
- **未ログインユーザー**: ランキングはサインアップ動機の入り口

### C.3 ユーザーストーリー
- 農家として、トップ 10 を見て「とりあえずこの中から選ぶ」判断ができる
- 農家として、自分の作目（例: イチゴ）でフィルタしたランキングが見たい
- メーカーとして、自社資材の現在順位がわかる（`/maker/products` に表示？）

### C.4 画面要素
- `/ranking` メイン
  - タブ（v1 で必要か議論）: 「総合」「カテゴリ別」「作目別」「期間（直近 3 ヶ月）」
  - 順位カード: 順位 (1-10)、製品画像、メーカー名、製品名、★評価、レビュー件数、含有成分タグ、効果タグ、概要、詳細リンク
  - 1-3 位は強調デザイン（メダル風）

### C.5 主要データ項目
- 既存 `reviews` テーブルから集計（追加テーブル不要、ビューで対応可）
- `product_ranking_view`: product_id, avg_rating, review_count, last_review_at（マテリアライズドビューで日次更新も検討）

### C.6 ロール権限
- 閲覧: 全ユーザー（未ログイン含む）
- 操作: 不要（読み取り専用）

### C.7 v1 スコープ外（推奨）
- 期間別フィルタ（直近 1 ヶ月 / 半年 / 1 年）
- カテゴリ別タブ（BS 分類別）
- 作目別ランキング
- 「メーカー別」「地域別」ランキング
- お気に入り数 / 閲覧数ランキング（PRD §6 インセンティブ系と境界）

### C.8 Claude 案（叩き）
**推奨: v1 は「総合 TOP 10 のみ」。`/leaderboard` は `/ranking` にリダイレクト統一。**

理由:
- レビュー数が少ない初期はカテゴリ別を出すと "1 件しかないのに 1 位" のような違和感が出る
- ★評価平均は最低レビュー件数（例: 3 件以上）でフィルタすべき。条件を絞れば総合 1 つで十分
- 不正対策（自社レビュー水増し）は v1 は監視のみ、検出ロジックは v1.5+
- `/ranking` と `/leaderboard` の二本立ては混乱の元、片方に寄せる

## D. メーカー公開ページ `/manufacturers` ⚠️

### D.0 機能サマリ
メーカーの企業プロフィールを一般公開し、自社資材一覧と紐付けて見せるページ。

### D.1 MVP 観測 / 現状
- MVP `/manufacturers` でカード一覧が実装されている
- カード項目: ロゴ、企業名、製品数、強み・特徴、提供価値、本社所在地、業種、詳細リンク
- 詳細パス: `/manufacturers/{slug}`（例: `/manufacturers/denka`）
- 既存 PRD: 未記載（メーカー側機能は `/maker/products` のみ）

### D.2 ユーザーとゴール
- **農家**: 信頼できるメーカーかを所在地・実績で判断したい
- **メーカー**: 自社の存在を一般公開して認知獲得したい
- **JA 普及員**: 組合員提案時にメーカー情報の正典として参照したい

### D.3 ユーザーストーリー
- 農家として、ある資材を見たあとで「どんな会社が作っているのか」をワンクリックで確認できる
- 農家として、メーカー詳細から自社製品一覧を見て横展開検討できる
- メーカーとして、自社プロフィール（ロゴ・説明・所在地）を編集できる

### D.4 画面要素
- `/manufacturers` 一覧
  - メーカーカード: ロゴ、企業名、製品数、強み（箇条書き 3 件まで）、本社所在地、業種、詳細リンク
  - 検索（v1 含むか要決定）
  - フィルタ（業種・地域、v1.5+ 推奨）
- `/manufacturers/{slug}` 詳細
  - ヒーロー: ロゴ + 企業名 + 業種
  - 概要セクション: 強み、提供価値、本社所在地、設立年（任意）、Web サイト URL
  - 自社製品一覧（既存 `/products` の `ProductCard` を流用）
  - レビュー集計（v1.5+: 自社製品全体の★評価平均）
- `/maker/profile` 編集画面（メーカー用）
  - ロゴアップロード、企業名、強み（最大 5 件）、提供価値、所在地、設立年、Web サイト URL
  - 公開／非公開切替

### D.5 主要データ項目
- 既存 `maker_profiles` テーブル拡張
  - 追加カラム候補: `slug` (UNIQUE), `logo_url`, `strengths` (text[] or JSONB), `value_proposition`, `headquarters`, `industry`, `website_url`, `founded_year`, `is_public` (bool, default true)

### D.6 ロール権限
- 閲覧: 全ユーザー（未ログイン含む）
- 編集: 自社のみ (`maker_id = auth.uid()`)
- 公開／非公開切替: 自社（v1 は全公開、切替は v1.5+ でも可）

### D.7 v1 スコープ外（推奨）
- メーカーフォロー機能
- メーカーから農家への直接メッセージ
- メーカー認証バッジ（運営承認）
- お問い合わせフォーム（メーカー向け）
- 業種・地域フィルタ

### D.8 Claude 案（叩き）
**推奨: v1 で公開一覧 + 詳細 + メーカー側編集画面までフル実装。検索/フィルタは v1.5+。**

理由:
- 既存 `maker_profiles` テーブル活用、軽量実装可能
- メーカー登録動機を高める（自社プロフィールが公開される）
- 検索/フィルタは登録メーカー数が少ない初期は不要（10 社程度なら一覧で見渡せる）
- spec 起草着手予定（既に Ryoga 確認済み）

## 1. 「推奨効果」の選択者 ⚠️

### 1.0 サマリ
資材の「推奨効果」（JBSA 効果タグ）を、メーカーが宣伝として選ぶか、農家がレビューで選ぶか、両方独立に持つか。

### 6.1 影響範囲
- 監査性（不適切な削除の追跡）
- 法的対応（開示要求への対応）
- メーカー信頼（メーカーが「都合悪いレビューが消された」と思う可能性）
- DB サイズ

### 6.2 選択肢

| 案 | 内容 |
|---|---|
| **案 1: hard delete + 監査ログ**（現状、Claude 推奨 v1） | 物理削除、削除イベントを別テーブル / Sentry に記録 |
| **案 2: soft delete** | `deleted_at` カラムで論理削除、復元可能 |
| **案 3: 削除前にスナップショット** | hard delete 直前に内容を別テーブルに保存 |

### 6.3 Claude 案（叩き）
**推奨: v1 は案 1。複雑化したら案 2 / 3 に移行。**

理由:
- soft delete は RLS が複雑になる（削除済みを除外するロジック）
- 削除頻度が少ない初期は監査ログで十分
- ストレージコスト（画像）は hard delete で消す方が経済的

### O.1 関連法令と Farmille への影響

| 法令 | 影響領域 | 対応必要度 |
|---|---|---|
| **個人情報保護法** | ユーザー登録、レビュー投稿、退会対応 | 🔥 必須 |
| **特定商取引法** | 運営者情報明示、メーカー有料化時の表示 | 🔥 v1 から必須 |
| **景品表示法** | レビュー表示、ランキング、効果効能表現、メーカー優劣表現 | 🔥 必須 |
| **景表法 ステマ規制（2023-10〜）** | メーカーから対価受領のレビューは「広告」明示必須 | 🔥 v1 から必須 |
| **農薬取締法** | 農薬の使用方法に関するレビュー / コメント | ⚠️ 投稿カテゴリで分岐 |
| **薬機法（参考）** | BS 資材は対象外だが、表現規制の参考になる | 💡 |
| **著作権法** | メーカーロゴ、製品画像、ブログ画像 | ⚠️ |
| **GDPR**（EU ユーザー対応） | EU 居住者がアクセスする可能性 | 💡 v1 は日本国内優先 |

### O.2 v1 で整備すべき法務対応

|---|---|
| 利用規約 | 弁護士確認（workshop §H） |
| プライバシーポリシー | 同上 |
| 運営者情報（特商法） | フッター or `/about` に記載 |

| レビュー表現ガイドライン | 投稿フォームに注意書き「治癒・絶対効果の表現を避ける」 |

### O.3 レビュー表現規制の具体例

**避けるべき表現** (景品表示法 / 農薬取締法 / 業界自主規制):
- 「絶対に効く」「100% 効果がある」「最高の○○」
- 「○○病が治った」（治癒表現）
- 「副作用ゼロ」「天然だから安全」
- 「他社製品より優れている」（比較表現）
- 農薬の登録外使用法の推奨

**許容される表現**:
- 「私の圃場では収量が増えた印象」
- 「△△の症状が軽減された気がする」

各ロールの **エンドツーエンド業務フロー**（通常 + 例外）を可視化し、抜け漏れを防ぐ。Web 検索結果より「通常業務フローだけでなく例外業務フロー（クレーム対応等）も整理」が要件抜け漏れ防止に有効と確認。

### U.1 想定される業務フロー（網羅チェック用）

**通常フロー**:
1. 農家サインアップ → ロール選択 → オンボーディング → 製品検索 → レビュー閲覧 → レビュー投稿 → マイページ確認
2. メーカーサインアップ → メーカーオンボ → 自社プロフィール編集 → 製品登録 → レビュー監視（v1.5+）
3. 未ログインユーザーの製品閲覧 → サインアップ動線
4. AI 検索（B Farmille AI）→ 結果クリック → 製品詳細 → レビュー投稿
5. メーカー → 自社製品レビュー閲覧 → 改善（v1.5+）

**例外フロー**:
1. **不適切レビュー通報** → 運営確認 → 削除 → 投稿者通知（要決定）
2. **メーカー異議申立** → 運営確認 → 判断 → メーカー通知
3. **個人情報削除依頼** → 受付 → 確認 → 削除 → 通知（法令 14 日以内）
4. **退会** → 確認 → アカウント無効化 → レビュー扱い決定
5. **メーカー担当者交代** → 旧担当者 → 新担当者へ引き継ぎ → アカウント譲渡（v1.5+）
6. **パスワード忘れ** → リセットメール → 新パスワード設定 → ログイン
7. **メールアドレス変更** → 新メアド入力 → 確認メール → 切替
8. **障害発生** → 運営認識 → 公式 X 告知 → 復旧 → 事後報告
9. **マスタデータ追加要望** → メーカーが `/contact` → 運営判断 → SQL 直編集 → 通知

### U.2 v1 スコープ外（推奨）
- 業務フロー図の Lucidchart / Miro での詳細化（v1.5）
- 自動化されたワークフロー（Zapier 等）
