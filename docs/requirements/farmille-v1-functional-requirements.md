## 1. プロダクトコンセプト（v1）

### 1.1 v1 のポジショニング: AgList + Carview MyCar 参照モデル

2026-04-29 会議で v1 は「カービュー × アグリスト」中間モデルとして定義された。本書では参照プラットフォームをさらに具体化し、**AgList（製品 / 企業 / 記事の 5 軸ハブ構造）+ Carview MyCar（マイ資材の保管 + 候補併存）**を 6 画面の参考形とする（ホーム画面の UI 構成はアイハーブを参照）。

| 参考プラットフォーム | Farmille v1 が踏襲する点 | Farmille で補完する欠落（差別化） |
|---|---|---|
| **AgList**（agriculture review） | 「製品 / 企業 / 記事 / 販売店 / 推薦」5 軸ハブ構造 / フィルタ（location / crop / feature）/ メーカー自記の企業ページ / leaderboard 別建て | お悩み相談室、講演会機能、公式返信、否定的レビュー（★1-5）、編集体制透明化された記事、運営による公式マーク |
| **Carview MyCar** | 最大 10 台保管 / 「所有」+「欲しいクルマ（候補）」の両方を保管 / 1 台あたり管理項目（車検・保険・オイル交換）/ 通知（車検・保険更新・適合パーツ） | （MyCar 単体にプロフ UI なし → みんカラ参考で農家プロフ画面を補完） |
| **みんカラ**（Carview 系コミュニティ） | ユーザーページのリッチ実装（プロフィール表示・自身の投稿一覧） | – |
| カービュー（車情報サイト） | 専門家レビュー・ユーザーレビュー・関連製品表示 | – |
| アグリスト（農業 SNS、AgList 表記揺れ） | メールベース問い合わせ（「使用版に興味がありますか？」型 CTA） | – |
| 食べログ | レビュー 200 件以上で星評価導入 / ユーザー信頼度で重み付け（v1 は星評価ありでも自動ランキングなし） | – |
| **アイハーブ** | ホーム画面 UI 構成（検索バー / 広告 / 注目商品 / 記事一覧） | – |

v1 は「コミュニティ・AI・自動ランキング」を持たない**レビュー / カタログ / 企業情報 / マイ資材 / 農家プロフ**を中心とする。

### 1.2 v1 ターゲットと提供価値

PRD §1.2 / §1.3 を継承。**v1 中心は farmer**。JA 普及員 / 研究者は v1 では農家と同等ビューを共有する読み手 + 投稿者として振る舞う（専用ビューは未確定、§5.3）。

| ロール | v1 の核体験 |
|--------|------------|
| 農家（farmer） | 6 画面全体が想定 UX。圃場条件に近い実例レビューを横断検索 / マイ資材で気になる資材を保管 / メーカーから「使用版」オファーを受け取る |
| JA 普及員（ja_staff） | 農家と同等ビュー。組合員提案エビデンスとしてレビュー閲覧、普及員視点でのレビュー投稿 |
| 研究者（researcher） | 農家と同等ビュー。現場データへのアクセス、専門的視点でのレビュー投稿 |
| メーカー（maker） | 自社資材登録（既存 `/maker/products`）・メーカー公開ページ運用（§3.3 連動）/ お悩み相談室応答（業務フロー未確定） |

### 1.3 「中立的情報インフラ」のポジション

PRD §9.3 を継承。v1 段階から以下を維持する。

- 農家側の体験は無料・広告なし（自社記事・月次レポートは掲載するが、メーカー有償広告枠は v1.5+、アフィリエイト広告は v1〜v3 不採用）
- メーカー課金の入り口を v1 では作らない（B2B LP は §4 v1 アウト、再検討は §5.4）
- 自社製品販売は行わない

## 2. ロール定義

### 2.1 ロール一覧と v1 での扱い

PRD §3 を継承。

| ロール | 内部キー | 登録方法 | v1 の核機能 | v1 専用ビュー |
|--------|----------|---------|------------|--------------|
| 農家 | `farmer` | サインアップで自己選択 | 6 画面の主役 / レビュー投稿 / マイ資材 / 検索 | 6 画面全体 |
| JA 普及員 | `ja_staff` | 管理者割当（v1 はサインアップ不可） | 農家と同等のレビュー権限 | なし（農家ビュー共有） |
| 研究者 | `researcher` | 管理者割当（v1 はサインアップ不可） | 農家と同等のレビュー権限 | なし（農家ビュー共有） |
| メーカー | `maker` | サインアップで自己選択 → **pending（マーケット非公開）→ アドミン承認 → active**（§3.9 B1） | 自社資材登録 / メーカー公開ページ運用 / お悩み相談室応答 / 公式返信 / 講演会主催 / 一斉メール送信 | `/maker/*`（§3.7 拡張ダッシュボード） |
| 運営 | `admin` | サインアップ経路なし。既存ユーザーを手動昇格（信頼ベース） | アドミン画面の全運営機能 | `/admin/*`（§3.9） |
| 未確定 | `unassigned` | サインアップ直後 | プロフィール設定のみ | – |
| 未ログイン | （なし） | – | 製品 / メーカー / 注目の資材 / 記事 / 企業 の閲覧 | – |

> **メーカー登録の pending フロー（2026-05-13 確定）**:
> - サインアップ時必須項目: 会社名 / 担当者名 / 連絡先メール（最小セット）
> - サインアップ直後 `users.status = 'pending_review'` で**マーケット非公開**（`/manufacturers` / `/products` から見えない）
> - メーカーは `/maker/*` にログイン可能、製品の下書き登録可能だが公開されない
> - アドミンが §3.9 B1 画面で承認 → `status = 'active'` 化 → マーケット公開
> - 偽メーカー判定時は `status = 'frozen'` / `'rejected'` へ

> **JA 普及員 / 研究者**の専用ビュー、サインアップ後のロール別ビュー分岐ルールは**未確定**（§5.3）。実装提案も着手もしない。

### 2.2 二層構造（実装観点）

ロールは Supabase Auth の `app_metadata.role`（JWT 由来、改ざん不可）と `public.users.role`（DB 列、SQL 集計用）の両方に保持する。書き込みは必ず `POST /v1/auth/register-role` 経由で原子的に両方更新する。

詳細は `docs/decisions/0002-reviews-insert-role-scope.md` 参照。

## 3. v1 で「やる」: 農家さん向け 6 画面（L3 詳細）

> 本章が v1 機能要件の中核。各画面で L3 8 サブセクションを完備する。

### 3.1 ホーム画面 🟡

#### 3.1.1 機能サマリ
未ログイン向けランディングとログイン済 `/home` の双方で、検索バー上部・自社記事広告枠・注目の資材（手動キュレーション）・記事一覧（月次〜週次レポート）を AgList の 5 軸ハブ構造とアイハーブの UI 構成を組み合わせて提供する。

#### 3.1.2 ユーザーとゴール
- 未ログイン訪問者: 検索バーから興味ある資材へ直行する / 「Farmille は何のサイトか」を即理解する / SEO 流入の入口
- 農家（ログイン済）: 注目の資材と最新記事を眺めて、知らなかった資材に出会う
- メーカー: 自社記事・自社資材が露出する場として認識する

#### 3.1.3 ユーザーストーリー
- 未ログインの農家として、トップページの検索バーに作目名や悩みを入れて、関連資材一覧に飛びたい。最初に知りたいのは「どの資材があるか」だから。
- 農家として、ホームに並ぶ「注目の資材」を眺めて、自分の作目で使えそうな新規資材を見つけたい。検索クエリを思いつかない時の入口にしたい。
- 農家として、月次〜週次レポート記事を読んで、業界トレンドや BS 資材の使い方の知見を得たい。
- メーカーとして、自社製品が「注目の資材」に手動掲載されることを期待する。

#### 3.1.4 画面要素
- `/`（未ログイン）と `/home`（ログイン済）で同じ構造。出し分けはヘッダーのログインボタン / アバターのみ
- **上部**: 検索バー（カタログ §3.2 への入口）+ メインビジュアル
- **広告 / 自社記事エリア**: 1〜3 枠。初期は自社記事・キャンペーン告知。将来的にメーカー広告枠化（v1 は自社のみ、メーカー有償広告枠は v1.5+）
- **「注目の資材」セクション**: 横並び 4-8 製品（AgList の leaderboard を参考にしつつ、**手動キュレーション**で運営が選定。自動ランキングではない）
- **「月次〜週次レポート / 記事」一覧**: 直近 3-6 件。タイトル・サムネイル・公開日
- **フッター**: 静的ページ（利用規約 / プライバシーポリシー / お問い合わせ / About）への導線

#### 3.1.5 主要データ項目
- `featured_products`（**所有節は本節**、新規）: 運営手動投入の「注目の資材」キュレーション用テーブル。カラム構成は spec 起草時 DOA レビューで確定（運営手動運用を前提に最小カラム設計）
- `articles` — 記事の参照元（**正は §3.4.5**、本節は読み取り参照のみ）
- `home_banners`（**所有節は本節**、新規）: 自社記事 / キャンペーン告知用。カラム構成は spec 起草時 DOA レビューで確定

#### 3.1.6 ロール権限
- 閲覧: 全ユーザー（未ログイン含む）
- 編集: 運営（v1 は SQL 直アクセス、管理画面は v1 アウト）

#### 3.1.7 v1 スコープ外
- メーカー有償広告枠購入 UI（v1.5+）
- パーソナライズドレコメンド（行動履歴ベース、SKILL §1.4 やらない）
- 「注目の資材」の自動選定ロジック（SKILL §1.4 やらない、手動キュレーションで代替）
- アフィリエイト広告（v1〜v3 不採用）

#### 3.1.8 残課題
§5.2.7 / §5.2.6 / §5.2.14 を参照。

### 3.2 製品（一覧 + 詳細）✅+🔥

#### 3.2.1 機能サマリ
BS 資材を中心とした製品カタログ。フィルタ付き検索の一覧と、★1-5 レビュー（本文 + 写真）・関連資材・「使用版」CTA を含む詳細ページから成る。AgList の製品ページを参考とし、AgList にない**否定的レビューも書ける**点で差別化する。

#### 3.2.2 ユーザーとゴール
- 農家: 作目・効果・成分でフィルタして候補を絞る / 詳細ページのレビューで業務判断する / 「使用版」CTA でメーカーから案内を受け取る
- JA 普及員: 組合員に推奨する前にレビュー確認のエビデンスを取る
- 研究者: 特定成分・効果の資材を横断的に調べる
- 未ログイン: SEO 経由で詳細に到達 → サインアップ動機につなげる

#### 3.2.3 ユーザーストーリー
- 農家として、作目「イチゴ」と効果「収量増加」でフィルタした一覧から、レビュー件数の多い資材を選んで詳細を読みたい。
- 農家として、製品詳細ページで★評価分布と本文 1-2000 字のレビュー（写真付き）を読んで、自分の圃場に応用できるか判断したい。
- 農家として、製品詳細ページの「関連資材」から類似製品に遷移したい。比較検討しているから。
- 農家として、製品詳細でメーカーが投稿したレビューへの**公式返信**を読み、メーカーの対応姿勢を判断したい。
- 農家として、製品が **「公式マーク」**（運営による安全性確認済みバッジ）を持っていれば信頼性のシグナルとして参考にしたい。
- メーカーとして、自社製品の詳細ページが正しく表示されることを確認したい。

#### 3.2.4 画面要素
- **一覧**: `/products`（本リポ実装）/ `/bs-materials`（MVP） — **URL 命名は §5.2 で要決定**
  - フィルタ: タイプ（BS資材 / 農薬 / 肥料 / 土壌改良材）、作目カスケード（大 6 / 中 27 / 個別 547）、BS 製品分類（8 種）、BS 主たる効果・効能（約 20 項目）
  - 表示: 製品カード（画像 / 製品名 / メーカー名 / ★評価 / レビュー件数 / 効果タグ）
- **詳細**: `/products/[id]` / `/bs-materials/[id]`
  - 上部: 製品名・メーカー名（リンク先 §3.3）・画像・含有成分タグ・効果タグ・概要・**公式マーク（運営付与時のみ表示）**
  - レビュー: ★評価分布（1-5）/ レビュー一覧（本文 1-2000 字 + 写真最大 3 枚）/ レビュー投稿ボタン（要ログイン）
  - **公式返信**: 各レビューの下にメーカー（公式）の自由文返信を表示（食べログ風、「メーカー公式」ラベル + アバター）
  - 関連資材: **同 BS 分類 + 同主要効果**ベース（行動履歴ベースは v1 アウト）

#### 3.2.5 主要データ項目
既存 `products` / `reviews` / `manufacturers` / `crops` / `product_crops` / `product_categories` / `product_effects` テーブルを活用。

**v1 で追加するもの**（DOA レビューは spec 起草時）:
- `products` テーブルに `is_official` boolean / `official_marked_at` / `official_admin_note` を追加（公式マーク、所有節は §3.9 B4）
- `review_replies`（新規、所有節は §3.7）: メーカー公式返信。`id, review_id, maker_id, body, created_at, updated_at`

関連資材は v1 では「同 BS 分類 + 同主要効果」での絞り込みクエリで実現する（埋め込み・行動ベースは v2-v3）。

#### 3.2.6 ロール権限
- 閲覧: 全ユーザー
- レビュー投稿動線（要ログイン）: farmer / ja_staff / researcher（投稿仕様は既存 spec `review-post.md`）
- 公式返信投稿: maker（自社製品のレビューのみ、§3.7 連動）
- 編集: メーカーは自社製品のみ（既存 spec `maker-product.md`）
- 公式マーク付与: admin（§3.9 B4）

#### 3.2.7 v1 スコープ外
- 行動履歴ベースの関連資材レコメンド（v2-v3）
- 自然言語検索（v2 以降、AI 機能と一体）

#### 3.4.4 画面要素

### 3.8 講演会機能 🆕

#### 3.8.1 機能サマリ
メーカーが講演会・セミナーを Farmille 上で告知し、農家・ユーザーから申込を受け、申込者・暗黙フォロワーに一斉メール案内できる機能。Farmille のメインマネタイズ動線（biz 2026-05-06 確定）。v1 は告知 + 申込フォーム + 一斉メール のみで、開催形式・参加費・録画提供などは本文の自由記入で運用する。

#### 3.8.2 ユーザーとゴール
- メーカー: 自社の講演会・セミナーで農家リードを獲得し、自社製品の認知度を上げる
- 農家 / JA 普及員 / 研究者: 興味あるメーカーの講演会を見つけて参加し、業務知見を得る
- 運営: メーカーの再訪動機 + マネタイズ動線を提供する（v1 は無料、v1.5+ で有料化）

#### 3.8.3 ユーザーストーリー
- メーカーとして、新しい講演会を企画して、Farmille 上に告知ページを作りたい。本文は自由記入で、開催形式（オンライン / オフライン）・参加費・アクセス・録画提供有無を書きたい。
- メーカーとして、講演会を作成した直後に、自社製品をマイ資材に保管中の農家へ案内メールを一斉送信したい。
- 農家として、興味あるメーカーの企業ページ / 講演会一覧（`/events` 仮）で講演会を見つけて、申込ボタンを押したい。
- 農家として、申込後にメールでリマインダーを受け取りたい（v1 は申込確認メールのみ、リマインダーは v1.5+）。
- 運営として、運営主催の講演会（例: 「BS 資材の使い方セミナー」）をアドミン画面から手動作成したい。
- 運営として、不適切な講演会内容（薬機法違反 / 詐欺）を通報・削除できる（§3.9 B2 連動）。

#### 3.8.4 画面要素

- **一覧**: `/events`（URL 仮）
  - フィルタ: メーカー / 開催日（今後 / 過去）/ 開催形式（タグ）
  - カード: 講演会タイトル / 主催メーカー名 + 公式マーク表示 / 開催日 / 申込数 / サムネイル
- **詳細**: `/events/{id}`
  - 上部: タイトル / 主催メーカー（リンク先 §3.3）/ 開催日 / 定員 / 申込締切
  - 本文: markdown レンダリング（開催形式 / アクセス / 参加費 / 録画提供有無 / その他案内 = 自由記入）
  - 「申込」ボタン → モーダルで簡易申込フォーム（氏名 / メール / 備考）→ 送信 → 確認メール
  - 申込後の表示: 「申込済」バッジ + キャンセルボタン（v1 採否は spec 起草時）
- **企業ページからの導線**: §3.3.4 講演会一覧セクション
- **メーカー側 CRUD**: §3.7.4 `/maker/events`
- **アドミン側**: §3.9 B7 拡張で運営主催講演会を手動作成（運営主催の場合は `host_type = 'admin'`）

#### 3.8.5 主要データ項目

- `events`（**所有節は本節**、新規）: `id, host_type ('maker' | 'admin'), host_maker_id (nullable), title, body, hero_image_url, event_date, deadline_date, capacity, status, created_by, created_at, updated_at`
- `event_registrations`（**所有節は本節**、新規）: `id, event_id, user_id, name, email, message, status, registered_at`
  - status enum: `registered` / `cancelled` / `attended` 等（spec 起草時に確定）

#### 3.8.6 ロール権限

| 操作 | 権限 |
|------|------|
| 一覧 / 詳細閲覧 | 全ユーザー（未ログイン含む） |
| 申込 | 全ログインユーザー（farmer / ja_staff / researcher / maker） |
| 講演会作成（メーカー主催） | maker（active 状態の自社のみ） |
| 講演会作成（運営主催） | admin（§3.9 B7 経由） |
| 編集 / 削除 | 主催者本人（maker は自社のみ）または admin |
| 申込者リスト閲覧 | 主催者本人または admin |

#### 3.8.7 v1 スコープ外

- Farmille 内での参加費徴収（決済システム v1.5+、v1 はメーカーが本文に外部決済リンクを記載 or 当日現金で運用）

- リマインダーメール自動配信（v1 は申込確認メールのみ、リマインダーは v1.5+）
- 申込キャンセル UI（v1 は spec 起草時に最低限の取消を入れるかを判断）

- カレンダー連携（iCal / Google Calendar）
- 講演会後のアンケート / フィードバック収集
- 公開後の本文構造化（v1.5+ で開催形式 / 参加費 / 録画提供有無を構造化フィールドに分離）
- 千人規模のメーカー主催イベントの大量通知最適化

#### 3.8.8 残課題

- 申込時の最低項目（メールのみ? 名前要? 住所必要?）
- メーカーから申込者への一斉案内メールの法規制対応（特商法 / 電気通信事業法、規約条項）

- 過去開催イベントの保存期間 + アーカイブ表示の有無

### 3.9 アドミン画面 🆕

#### 3.9.1 機能サマリ
運営チーム（共同創業者 3 名 + 必要なら 1-2 名追加）が日常運用で使う `/admin/*` ハブ画面。メーカー承認 / 通報管理 / 記事 CRUD / 公式マーク付与 / ユーザー・ロール管理 / 注目の資材キュレーション の 6 サブ画面で構成する。SKILL §1.4「管理者画面 v1 アウト」の反転（2026-05-13）に伴い v1 必達。

#### 3.9.2 ユーザーとゴール
- 運営: 日常運用（メーカー承認 / 通報対応 / 記事公開 / 公式マーク判定）を 1 つの管理画面で完結させる
- 運営: SQL 直アクセスの運用負荷を下げ、ヒューマンエラーリスクを減らす
- メーカー / 農家: 運営の対応速度が上がり、健全なコンテンツ環境が維持される

#### 3.9.3 ユーザーストーリー
- アドミンとして、pending メーカーの一覧を見て、各社の登録情報を確認 → 承認 / 却下 / 凍結 を 1 ボタンで処理したい。
- アドミンとして、通報されたコンテンツ（レビュー / スレッド / プロフィール）の一覧を見て、削除 / 却下 / 警告 を判断したい。メール通知で気付けるようにしたい。
- アドミンとして、週次レポートを **note のような便利なエディタ**で執筆 → 公開したい。Wordpress 並みではなく markdown ベースの軽量エディタで OK。
- アドミンとして、メーカー / 製品単位で **公式マーク**を on/off できる UI が欲しい。判定理由は運営メモに記録したい。
- アドミンとして、JA 普及員 / 研究者の申請を受けて、SQL を書かずにロール付与したい。アドミン昇格も同じ画面で。
