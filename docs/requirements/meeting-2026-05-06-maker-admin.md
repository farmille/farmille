# Farmille v1 メーカー × アドミン機能要件 議事録

## 0. 要約

v1 スコープに以下を **追加** した:
- **アドミン画面**（`/admin/*`、サブ画面 6 個、2FA 必須）
- **講演会機能**（CRUD + 申込フォーム + メーカー主導の一斉メール）
- **公式返信機能**（食べログ風、レビューへのメーカー自由文返信）
- **公式マーク付与**（アドミン目視で製品 / メーカー単位 on/off）
- **メーカー有料化条項**（v1 ローンチ時は無料、規約条項のみ追加、2026-06 以降課金開始予定）
- **メーカー登録 pending フロー**（マーケット非公開 → アドミン承認）

v1 スコープから **削除** したもの:
- **「使用版」CTA 一式**（`sample_requests` テーブル設計撤回、マイ資材「問い合わせ履歴」タブ廃止）
- **マイ資材のサイト内メーカー通知**（DM 法規制と「使用版」削除の流れで不要化）

**重大な反転**:
- SKILL §1.4「管理者画面 v1 アウト」→ **「v1 で作る」へ反転**
- PRD §9.3「メーカー有料化 v1 アウト」→ **規約条項として v1 で記載**（実装は v1.5+）
- workshop §M2「メーカー返信機能 v1 なし」→ **v1 採用**
- workshop §M4「使用版希望者リスト v1 採用」→ **「使用版」自体撤回**

## 2. 新規確定事項

### 2.1 メーカー側（M1〜M5 対応）

| ID | トピック | 決定 | 出典 |
|---|---|---|---|
| **M1** | メーカー拡張ダッシュボード `/maker` | **v1 採用**（カード 7 枚: プロフ / 商品 / レビュー + 公式返信 / お悩み相談 / 講演会 / 一斉メール / 公式マーク表示）| 2026-05-06 定例 |
| **M2** | レビュー集計通知 + 公式返信 | **v1 採用**。メーカー → レビューへの**自由文返信を許容**（食べログ風）。新規 `review_replies` テーブル | 2026-05-06 定例 |
| **M3** | お悩み相談室応答 | workshop §M3 推奨どおり **v1 任意応答 + 自由文** で継続 | 2026-04-29 継承 |
| **M4** | 「使用版」希望者リスト | **撤回**。M4 全体を v1 から削除 | 2026-05-13 worker |
| **M5** | メーカー承認フロー | **A + B 中間案: 誰でも登録 → pending（マーケット非公開）→ アドミン承認 → active 化**。承認は B1 アドミン画面で手動 | 2026-05-06 + 2026-05-13 worker |

#### M5 詳細（pending フロー）

- **pending = マーケット非公開**：`/manufacturers` 一覧 / `/products` から見えない。ログインは可能、製品下書き登録は可能だが公開されない
- **サインアップ必須項目**: 会社名 / 担当者名 / 連絡先メール（最小セット）
- **追加情報**は承認時にアドミンが運営メモとして記入: 法人番号 / 会社 URL / 業種 等
- **DB 設計**: `users.status` enum（`pending_review` / `active` / `frozen` / `rejected`）+ `app_metadata.role` 二層構造（ADR 0002 整合）
- **v1.5 移行トリガ**: メーカー数 50 社超 + 偽メーカー実害発生時に Yelp Claim 方式や法人 API 連携を検討

### 2.2 講演会機能（新規 §3.8）

biz 発言「**講演会がメインのマネタイズ**になる」を v1 完版採用。

| 項目 | 決定 |
|---|---|
| 採否 | **v1 完版採用** — CRUD + 申込フォーム + メール一斉配信を全て v1 |
| 主催 | **メーカー主催のみ**。運営主催はアドミン画面から手動作成 |
| 開催形式 | v1 = **告知ページ + 申込フォームだけ**。開催形式（オンライン / オフライン / 録画 / 参加費 / 定員）はメーカーが本文に自由記入 |
| メール一斉送信 | **メーカーがセグメントを選択可能**: 「自社製品をお気に入り / 候補に追加した農家」「個別ユーザー指定」など切替 |
| メーカーフォロー機能 | **暗黙フォロー**: 既存 `user_favorites` から `DISTINCT maker_id` で導出（新規テーブル不要） |
| 申込データ | 新規テーブル `events` / `event_registrations`（カラムは spec 起草時に DOA レビュー） |
| 参加費 / キャンセル / 録画提供 | **v1 はスキーマ化せず**、メーカー本文の自由記入。v1.5+ で構造化検討 |

### 2.3 公式マーク機能（v1 採用）

| 項目 | 決定 |
|---|---|
| 採否 | **v1 採用** |
| 判定基準 | **アドミン目視で手動付与**。製品単位 / メーカー単位の両方で on/off |
| 運営側 UI | アドミン画面 B4「公式マーク付与」サブ画面で on/off + 運営判断メモ記入 |
| 表示位置 | 製品詳細ページ / メーカー公開ページ / 製品カード（一覧時）に「公式」バッジ表示 |
| 判定材料 | SDS / ラベル情報 / 安全性データ（v1 では本文記入のみ）/ 過去のレビューの誠実な対応 等を運営が総合判断 |
| データ | 既存 `products` / `manufacturers` テーブルに `is_official` boolean + `official_marked_at` + `official_admin_note` を追加 |

### 2.4 SDS / ラベル情報

| 項目 | 決定 |
|---|---|
| v1 スキーマ化 | **やらない** |
| 代替 | メーカーが製品本文（既存 `products.description`）に自由記入 |
| v1.5+ | フォーマットを自前定義 → 構造化スキーマ + ファイルアップロードフィールド追加 |
| 公式マーク連動 | v1 ではアドミン目視判定の判断材料の一つ、自動連動なし |

### 2.5 メーカー有料化方針

| 項目 | 決定 |
|---|---|
| v1 ローンチ時 | **全メーカー無料** |
| 規約条項 | 「将来的にメーカーから月額料金（協力ベース、サーバー料相当の月 3,000 円程度）を徴収する場合がある」旨を v1 ローンチ時の規約に記載 |
| 課金開始時期 | 2026-06 以降（要 biz 確定） |
| 課金システム実装 | v1.5+（Stripe 等の選定 + 月次請求書 + 課金状況閲覧 UI） |
| 無料 / 有料の機能線引き | v1 ではスコープ外（全機能無料）。v1.5 で再決定 |

### 2.6 アドミン画面（新規 §3.9）

SKILL §1.4「管理者画面 v1 アウト」を反転。

| 項目 | 決定 |
|---|---|
| URL | `/admin/*`（同一 frontend 内、Vercel デプロイ） |
| ロール | 既存 5 ロールに **`role = 'admin'` を追加（6 ロール目）**。`app_metadata.role` 二層構造に乗せる |
| サインアップ | **公開経路なし**。既存 farmer / maker アカウントを SQL で手動昇格（biz「付き合いある人にしかアドミンはあげれない」） |
| 認証 | **2FA 必須**（Supabase Auth MFA）— 通報削除 / メーカー凍結 / ロール昇格 / 公式マーク付与 などの重操作のため |
| 母数想定 | 共同創業者 3 名 + 必要なら 1-2 名追加 |

## 3. v1 スコープ差分（追加 / 削除 / 延期）

### 3.1 v1 に追加されたもの

- アドミン画面 `/admin/*`（6 サブ画面、2FA、role='admin'）
- 講演会機能 §3.8（CRUD + 申込 + メール一斉、メーカー主催のみ）
- メーカーダッシュボード §3.7（7 カード）
- 公式返信機能（食べログ風、`review_replies` テーブル新規）
- 公式マーク機能（製品 / メーカー単位 boolean）
- メーカー登録 pending フロー（`users.status` enum）
- メーカー有料化規約条項（v1 ローンチ時の `/terms` に記載）

### 3.2 v1 から削除されたもの

- 「使用版」CTA 一式（`sample_requests` テーブル設計撤回）
- マイ資材「問い合わせ履歴」タブ
- マイ資材「サイト内メーカー通知」枠
- workshop §M4 全体

### 3.3 v1.5+ に延期したもの

- SDS / ラベル情報の構造化スキーマ（v1 は本文自由記入）
- 課金システム実装（Stripe 等）
- メーカー内の複数アカウント / 権限分離（S7、現状 1 メーカー = 1 アカウント）
- 規約バージョン管理 UI（B8）
- お問い合わせ受信 UI（B9）
- メーカーへの記事投稿権限
- 製品ページの Q&A / 安全性データ タブ（保留、次回確認）
- ホーム画面ランキングタブ（保留、次回確認）
- レビュー返信頻度による上位表示（公平性懸念、自動ランキング不採用と整合）
