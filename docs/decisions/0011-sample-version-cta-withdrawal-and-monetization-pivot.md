## 1. コンテキスト

`meeting_document.md`（2026-04-29 確定）では、メーカー × 農家の接点として **「使用版に興味がありますか？」CTA**（アグリスト型、メールベース）を v1 の AgList 差別化要素として採用していた。これは:

- 機能要件 §3.2.4 製品詳細ページの CTA
- 機能要件 §3.3.4 企業ページの CTA
- 機能要件 §3.3.5 `sample_requests` テーブル
- 機能要件 §3.5 マイ資材「問い合わせ履歴」タブ
- workshop §M4「使用版希望者リスト」

として複数の節に展開されていた。

2026-05-13 worker session で biz から「**使用版の機能いらない**」「**講演会がメインのマネタイズ**になる」と明確な発言があり、方向性が大きく転換した。

## 2. 決定

### 2.1 「使用版」CTA を v1 から完全撤回

- 機能要件 §3.2.4 / §3.2.5 から「使用版」CTA 記述を削除
- 機能要件 §3.3.1 / §3.3.4 / §3.3.5 から「使用版」CTA + `sample_requests` 記述を削除
- 機能要件 §3.5「問い合わせ履歴」タブを削除（**3 タブ → 2 タブに縮小**）
- 機能要件 §5.2.3「使用版業務フロー」未確定行を **解消（削除）**
- workshop §M4 全体を撤回（採用案を「やらない」へ移動）
- §1.1 §7.1 §7.2 の AgList 差別化要素から「使用版 CTA」を消し、講演会 + 公式返信 + メール一斉に置換

### 2.2 マネタイズ方針のピボット

- 旧: メーカー × 農家接点 = 「使用版」CTA（メーカーが農家リードを獲得）
- 新: メーカー × 農家接点 = **講演会機能 + メール一斉送信 + 公式返信**（§3.7 §3.8）
- メーカー有料化: 月 3,000 円・協力ベース（規約条項のみ v1、システム実装は v1.5+）

### 2.3 sample_requests テーブルの設計撤回

- v1 のスキーマに `sample_requests` テーブルを作らない
- 既に migration が書かれていたら revert（worker 側で確認 + revert PR）
- 関連する RLS ポリシー / FastAPI エンドポイントも撤回

### 2.4 マイ資材の縮小（3 タブ → 2 タブ）

- お気に入り（保管中）
- 候補（気になる）
- ~~問い合わせ履歴~~ ← 削除
- ~~サイト内メーカー通知~~ ← 削除（§5.2.4 解消）

## 3. 採用した代替案

### A. 「使用版」CTA を維持（却下）
- biz が「いらない」と明確に発言
- 法規制境界（DM 不採用）を踏まないようメールベースで設計していたが、運用負荷が高い
- メーカー × 農家接点としては講演会 + 一斉メールのほうが UX が良い

### B. 「使用版」を講演会に統合（却下）
- 「使用版を希望する農家リストを講演会で抽選提供」的な統合は biz 発言を超えた解釈
- 撤回が最もシンプル

### C. v1.5+ に延期（却下）
- biz が「いらない」と発言、復活する想定がない
- ドキュメント残置は混乱の元、完全削除が正しい

### D. 完全撤回（採用）
- biz 発言と整合
- マイ資材スコープも縮小、UX が単純化
- データモデルから `sample_requests` が消える → DOA 負荷軽減

## 4. 帰結

### Positive
- v1 スコープが簡素化（マイ資材 3 タブ → 2 タブ、`sample_requests` テーブル消滅）
- メーカー × 農家接点が「講演会 + 一斉メール + 公式返信」に集約され、設計が明快
- DOA レビュー軽い

### Negative
- 既に書き始めていた spec / migration を revert する必要（worker 側で確認）
- AgList 差別化要素が「使用版」から「講演会 + 公式返信」に変わったため、PRD / 機能要件 / SKILL の複数箇所を同期更新する必要
- 過去にメーカーに「使用版機能あります」と説明していた場合の説明変更（biz 側で対応）

### 中立
- 「使用版」需要が v1 ローンチ後に判明する可能性 → v1.5+ で再導入の余地は残す（ただし §5.4 にも残さない、完全撤回として扱う）

## 5. 移行手順

1. worker session で機能要件 md / workshop / SKILL の関連箇所を一括更新（完了済み）
2. 既存 spec / migration ファイルを grep して `sample_requests` 参照を全削除
3. spec 起草着手前のチェック: `sample_requests` がスキーマに残っていないか
4. 既存 PR / コミットがあれば revert
