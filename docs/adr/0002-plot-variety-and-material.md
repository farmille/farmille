# 実証詳細レポートの区に品種と使った資材を持たせる

区は名前と説明しか持たず、どの品種にどの資材を使った区かをデータで表せなかった。区を「試した品種」と「使った資材」の組み合わせとして持つ。品種と比較した資材はレポートごとの子テーブル（`usage_report_varieties`・`usage_report_compared_materials`）に置き、区はその行を指す。使った資材は投稿した資材・比較した資材・無処理のいずれかで、投稿した資材と無処理には行を作らない。全区に共通の説明を親レコードに1つ置き、区・品種・比較した資材の上限はそれぞれ40とする。

`form_version` は2のままにする。区に使った資材があるかどうかで新旧を見分け、無い区は今の1列の見え方で出す。品種と使った資材の必須は、下書きから提出に移るときだけ `app.assert_usage_report_plot_submission` で確かめる。公開の操作でも動く `app.assert_usage_report_submission` には緩める変更だけを入れ、提出済みの既存レポートをそのまま公開できるようにする。既存の form_version=2 の品種は子テーブルへ写し、`usage_reports.variety` は form_version=1 の記事のためだけに残す。

区の名前と説明の自由記述だけで表す案は採らない。品種ごとにまとめる表示や、PDF読み取りの結果を区に当てはめる処理が、文字列の解釈に頼ることになる。

`form_version` を3に上げる案も採らない。`form_version = 2` を比べる箇所がアプリと提出の検査に多くあり、1か所でも直し忘れると、新しいレポートが提出の検査を素通りする。

比較した資材をカタログの資材に紐づける案も採らない。カタログに無い資材や他社の資材とも比べるので、名前で持つ。レポートを出すのは投稿した資材のページだけとする。
