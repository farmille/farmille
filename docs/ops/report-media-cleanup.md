# 保存されなかったレポート画像の回収

`report-media`へアップロードしてから24時間以上経ち、保存済みのレポートが参照していない画像を回収する。タブを閉じた場合や、画像の削除に失敗した場合も対象になる。保存済みの下書き・確認中・公開済みのレポートが参照している画像は残す。

GitHub Actionsの`Remove expired report media`が毎時23分にdevと本番を検査し、各環境で1回100件まで削除する。実行時刻はGitHub側の混雑で遅れる場合がある。失敗はActionsの実行結果で確認し、同じworkflowを手動実行して再試行できる。GitHubの`production`環境にある既存の`SUPABASE_ACCESS_TOKEN`で、各環境のservice_role権限のsecret key（`sb_secret_…`）をManagement APIから取り出して使う。legacyの`service_role` JWTは使わない。マージ前に本番へ手動実行しない。

回収対象はDBで確保する。画像の参照を保存する処理と同じロックを取り、参照が増えていないことを確かめる。確保後の画像を保存しようとすると保存が失敗するため、24時間以上保存せずに開いていた画面では、画像を選び直して保存する。本文などの入力は残る。

削除にはStorage APIを使い、ファイル本体とメタデータを消す。削除に失敗した対象はDBに残り、次回も対象になる。DBの回収記録だけを消すと再び保存できてしまうため、復旧時も削除APIの再試行を使う。

ローカル検証では54321のSupabaseへmigrationを適用し、`NEXT_PUBLIC_SUPABASE_URL`と`SUPABASE_SECRET_KEY`をそのローカル環境に向けて`node src/server/cleanup-report-media.ts`を実行する。
